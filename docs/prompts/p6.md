# 5. GLOBAL ANTI-AI-SLOP REQUIREMENTS

These are hard requirements throughout Phase 04.

## 5.1 Prohibited visual patterns

Avoid:

- Unnecessary badges on every book.
- Repeated "Best Seller", "Popular", "Trending", or "Recommended" pills.
- Random decorative dots.
- Decorative circles around book covers.
- Large shadows beneath every product.
- Giant pill-shaped buttons.
- Excessively rounded cards.
- Generic feature grids.
- Floating elements with no functional purpose.
- Arbitrary gradients.
- Glow effects.
- Background patterns unrelated to the content.
- Excessive icons.
- Oversized section headings.
- Repeated information cards.
- Unnecessary dividers.
- Inconsistent spacing.
- Redundant CTA buttons.
- Artificial loading animations.
- Unjustified visual complexity.

## 5.2 Badges are functional, not decorative

Use a badge or status indicator only when it communicates information that genuinely helps the user.

Valid possibilities include:

- A verified content status supported by the specifications.
- A meaningful availability state.
- A required transactional status.

Do not place a badge on every book just to make the interface appear more complete.

## 5.3 No information duplication

Examples of duplication to avoid:

- Showing the book's publisher three times in different cards.
- Repeating the price beside every action.
- Displaying identical synopsis text in multiple sections.
- Showing the book format as a badge, card, and specification row simultaneously.
- Repeating the heading in a subtitle.
- Repeating an error message in a toast and a large panel.

Every element should contribute unique information or a clearly defined interaction.

## 5.4 Natural Indonesian copywriting

Use clear, concise, professional Indonesian.

Avoid artificial or overly enthusiastic copy.

Examples:

Bad:  
"Temukan keajaiban di setiap halaman buku!"

Better:  
"Detail Buku"

Bad:  
"Intip sedikit petualangan membaca yang menakjubkan!"

Better:  
"Preview Buku"

Bad:  
"Oops! Buku favoritmu sedang bermain petak umpet."

Better:  
"Buku tidak ditemukan."

Bad:  
"Yuk, lanjutkan perjalanan literasimu!"

Better:  
"Terakhir Dilihat"

Bad:  
"Belum ada jejak petualangan bacaanmu."

Better:  
"Belum ada buku yang dilihat."

The goal is straightforward communication, not forced personality.

## 5.5 Anti-slop self-review

For every major element, ask:

1. What information or action does this element provide?
2. Is the same information already visible elsewhere?
3. Does the design match the user's current task?
4. Would removing the element improve clarity?
5. Is the styling consistent with the rest of IKAPI?

Remove unnecessary elements.

Book covers are a critical part of F04.

## 6.1 Reuse the existing asset library

Start with book assets created or approved in Phase 01.

```

F04 Detail — Book A
    |
    | Preview
    v
F04 Preview — Book A
    |
    | Back
    v

```

Book A must retain:

- The same title.
- The same author.
- The same publisher.
- The same cover image.
- The same displayed price.
- The same category information.
- Consistent supported metadata.

Do not silently generate a different cover for the same book.

## 6.2 Image selection priority

Use assets in this order:

1. Existing approved IKAPI project assets.
2. Existing Phase 01 asset library.
3. Authorized publisher-provided covers or samples.
4. Appropriately licensed images for demonstrative content.

For real book titles, prefer authentic official covers with appropriate permission.

Do not create fake official-looking covers for real books.

For fictional demo books, clearly distinguish their identities from real publications.

If an asset is unavailable, record that limitation rather than silently inserting an unrelated image.

## 6.3 Image quality rules

Verify:

- Book covers remain proportional.
- Text on covers is not obviously distorted.
- Images are not stretched.
- Cropping does not remove important cover information.
- Thumbnails and large covers are consistent.
- Image resolution is suitable for the intended size.
- No broken or empty image frames remain.
- The same asset is reused across the design.

## 6.4 Do not fake book content

Book preview pages require additional care.

Do not invent text and present it as an authentic excerpt from a real copyrighted publication.

Use:

- Approved publisher sample pages.
- Public-domain book excerpts where appropriate.
- Clearly labeled, purpose-created demonstration content.

Do not copy unauthorized full books or expose private PDF assets.

Do not invent a fake preview for a real book while presenting it as authentic.

- E-book format.

Additional metadata may be displayed only when supported by project specifications or verified mock data, such as:

## 8.2 Recommended desktop hierarchy

This is a conceptual structure, not an instruction to reproduce an ASCII mockup literally.

## 8.3 Cover presentation

The book cover must remain visually prominent.

Do not:

- Place it inside multiple nested white cards.
- Surround it with random decorations.
- Add artificial glow or huge shadow.
- Stretch it to fill a square container.
- Crop away important title information.

Use an appropriate portrait aspect ratio and maintain the original visual identity.

## 8.4 Book identity and metadata

The primary text hierarchy should usually be:

1. Book title.
2. Author.
3. Publisher.
4. Price.
5. Other supporting metadata.

Avoid giving every item equal visual weight.

Price should be easy to locate without being repeated in multiple places.

## 8.5 Synopsis

The synopsis must be readable.

Use:

- Comfortable line length.
- Appropriate paragraph spacing.
- A clear heading.
- Sufficient contrast.

Do not:

- Force the synopsis into a tiny fixed-height box.
- Use excessively small text.
- Fill the area with generic AI-written prose.
- Repeat the synopsis elsewhere.

If the content is long, use an appropriate expansion behavior where helpful.

Avoid creating a separate full-screen frame for a trivial text expansion unless necessary to demonstrate interaction.

## 8.6 Book specifications

Display specifications through a readable information layout.

Prefer simple rows or definition-list-like structures.

Do not make each metadata item a separate decorative card.

For example:

```
Informasi Buku

Penerbit          Nama Penerbit
Format            PDF
Bahasa            Indonesia
Halaman           [Only if supported]
Tahun Terbit      [Only if supported]
```

Only include values actually available in approved book data.

## 8.7 Rating presentation

The use case expects rating information.

If rating data exists:

- Display it clearly.
- Use a restrained visual indicator.
- Keep the score and relevant count consistent.

If data is unavailable:

- Do not fabricate hundreds of ratings.
- Do not show a false rating distribution.
- Use a sensible empty or unavailable state.

Do not build the complete reviews and comment submission feature.

That belongs to F10.

# 10. UC-08 — BOOK PREVIEW SCREEN

Create a professional book preview experience.

Suggested frame names:

- `F04 / Preview / Default`
- `F04 / Preview / Unavailable`

The preview must look like a reading interface for a limited sample, not a generic PDF editor or full e-reader product.

## 10.1 Preview entry

The user arrives from the Book Detail page using the "Preview Buku" action.

The selected book's identity must remain consistent.

Use:

- The book title.
- Appropriate contextual navigation.
- A clear close or back action.
- Sample content pages.

Do not introduce an unrelated book title.

## 10.2 Preview layout

A suitable conceptual structure:

```
+--------------------------------------------------------------+
|  [Back]  Preview Buku: Judul Buku                            |
+--------------------------------------------------------------+
|                                                              |
|                +--------------------------+                  |
```

## 10.3 Sample content

Use a limited set of approved or clearly demonstrative sample pages.

Do not automatically download and reproduce full copyrighted books.

- Readable.
- Correctly proportioned.
- Consistent with the selected book.
- Clearly limited in scope.

- Previous page.
- Next page.
- Current page indicator.

- Annotation tools.
- Highlighting.
- Bookmarks.
- Download controls.

- Generic error artwork.

## 10.6 Loading or failure states

However:

- Do not create several redundant loading frames.
- Do not add fake progress indicators.
- Do not claim actual file loading or server activity in a static design.

- Cover.

- Showing a concise empty-state message.

"Belum ada buku yang dilihat."

- Decorative illustrations.

# 13. RESPONSIVE DESIGN REQUIREMENTS

Design for:

**Desktop**

- Follow the existing Phase 01 desktop viewport convention.
- Approximately 1440px wide unless the existing design uses another standard.

**Mobile**

- Follow the existing mobile viewport convention.
- Approximately 390px wide unless previously established otherwise.

**Tablet**

- Ensure the layout has a credible intermediate adaptation.
- Add a tablet frame when the layout behavior materially changes and requires explicit demonstration.

## 13.1 Desktop book detail

A desktop design may use a two-column layout:

- Cover on one side.
- Product information and actions on the other.

Below, longer textual content may use an appropriate reading width.

Do not spread a synopsis across an excessively wide line length.

## 13.2 Mobile book detail

On mobile:

- Stack content naturally.
- Keep the cover prominent but not oversized.
- Preserve readable titles.
- Keep price and actions visible.
- Avoid narrow columns.
- Avoid awkwardly wrapped buttons.
- Avoid sticky overlays that obscure content.

The mobile interface should be purposefully designed, not merely a compressed desktop frame.

## 13.3 Preview responsiveness

On mobile:

- Maintain readable sample pages.
- Provide accessible previous/next navigation.
- Keep close/back controls obvious.
- Avoid clipped pages.
- Avoid tiny controls.
- Avoid horizontal overflow unless a deliberate viewer interaction justifies it.

Do not scale an entire desktop reader down to fit the mobile screen.

## 13.4 Edge cases

Inspect:

- Long book titles.
- Long publisher names.
- Multi-paragraph synopsis.
- Different cover proportions.
- Missing ratings.
- Unavailable previews.
- Empty browsing history.
- Unavailable book details.

Correct layout defects before completion.
