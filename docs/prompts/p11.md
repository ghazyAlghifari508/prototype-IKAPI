## 3. Visual regression methodology

Untuk setiap halaman/state pilih viewport sama: `1440×900`, `1366×768`, `768×1024`, `390×844`, `320×700` jika relevan. Compare:

- screenshots full-page dan viewport, overlay/diff;
- bounding rect untuk header/hero/card/section/modal/sidebar;
- computed style font family/weight/size/line-height, colors, spacing, border radius, shadows, image dimensions/object-fit, max-width, breakpoints, z-index;
- text content, line wrapping, number of visible items, icon size, sticky/fixed geometry, no overflow.

**Fail** perbedaan seperti gambar/crop salah, Tailwind utility hilang, font lain, overflow, spacer berlebihan, wrong CTA/button states, nav collapse keliru, modal offset, card heights atau truncation yang tidak sesuai. Beri toleransi hanya kepada perbedaan rendering nondeterministic yang dijelaskan (mis. antialias font) dan terapkan stabilisasi, bukan threshold besar yang menyembunyikan bug. **Do not declare visual 100% if not tested.**

- `composer validate`, `php artisan route:list`, `php artisan view:cache`, `npm run build`, relevant test suite with DB-free constraints; do not run migrate/seed.

## 8. Defect workflow

For each failure: capture actual/expected, URL, viewport, state, screenshot/log/console/network, source HTML evidence, root cause, impacted files, smallest correct fix, retest and related regression. Do not patch source HTML to make diff pass. Avoid arbitrary CSS overrides that harm other pages; use component-scoped changes and rerun baseline snapshots.

Bug prioritization:

- P0: page won't load / crashes / data lost / routes broken.
- P1: major visual layout mismatch, missing section/assets, broken interaction.
- P2: alignment, text wrapping, hover/focus state discrepancies.
- P3: minor non-regressive cosmetic detail; still document if unresolved.

**No silent P2/P3 acceptance** if goal is no unapproved UI differences. Stop calling complete until defects resolved or explicit owner-approved exceptions documented.
