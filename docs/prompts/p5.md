# 5. DESIGN SYSTEM — NOTION-INSPIRED IKAPI

Continue using the Notion-inspired design language that was approved for the marketplace.

The objective is not to reproduce the Notion website.

Instead, adapt the following principles to a professional Indonesian e-book marketplace.

## 5.1 Core visual tokens

Use established design tokens whenever they exist.

Reference values:


| Token          | Value                                    | Usage                                   |
| -------------- | ---------------------------------------- | --------------------------------------- |
| Page Canvas    | `#F6F5F4`                                | Main page background                    |
| Card Surface   | `#FFFFFF`                                | Form surfaces and panels                |
| Primary Blue   | `#0075DE`                                | Primary actions and interactive accents |
| Primary Text   | `#111111` / established near-black token | Headings and text                       |
| Secondary Text | Existing muted text token                | Descriptions and helper text            |
| Border         | `rgba(0,0,0,0.08)`                       | Subtle boundaries                       |
| Sky Tint       | `#E6F3FE`                                | Restrained secondary-action styling     |


Typography:

- Prefer existing project typography styles.
- Use Inter as a fallback when NotionInter is unavailable.
- Preserve readable hierarchy.
- Keep form headings moderate and appropriate.
- Use consistent field labels, helper text, and validation messages.

Shapes:

- Form inputs should use established component radii.
- Buttons should generally use the existing 8px radius.
- Cards and grouped surfaces should generally use the existing 12px radius.
- Do not use pill-shaped controls unless there is a genuine functional reason.

Borders and elevation:

- Prefer hairline borders.
- Avoid large shadows.
- Avoid decorative gradients.
- Avoid glowing panels or excessive visual effects.

## 5.2 Authentication-specific interpretation

Authentication screens must prioritize clarity, trust, and form usability.

Unlike a promotional landing page, an authentication page does not require:

- Huge hero typography.
- A decorative slogan.
- Multiple colored accent panels.
- Floating illustrations.
- Numerous marketing feature cards.
- Large background gradients.
- Decorative book graphics unrelated to account access.

A clean authentication form with strong typography and sensible spacing is preferable.

# 6. MANDATORY ANTI-AI-SLOP RULES

These requirements apply to every frame in this phase.

## 6.1 Visual anti-slop

Do not create:

- Excessive badges.
- Decorative status pills.
- Random colored dots.
- Unnecessary geometric ornaments.
- Giant rounded containers.
- Oversized shadow effects.
- Generic SaaS dashboard aesthetics.
- Floating glass panels.
- Unnecessary gradients.
- Artificial glow.
- Decorative arrows and squiggles.
- Repetitive icons beside every label.
- Too many nested cards.
- Unjustified large empty areas.
- Multiple primary buttons competing for attention.
- Redundant headings or supporting descriptions.

Do not place elements on the screen merely because they make the design appear more complex.

Every element must have a clear purpose.

## 6.2 Copywriting anti-slop

All user-facing text must use clear, natural, professional Indonesian.

Avoid:

- Exaggerated enthusiasm.
- Cringe marketing language.
- Unnecessary motivational copy.
- Robotic interface descriptions.
- Repeated instructions.
- Redundant helper text.
- Excessive technical terminology.
- Generic AI-generated slogans.

Examples:

Bad:  
"Selamat datang di perjalanan literasi tanpa batas!"

Better:  
"Masuk ke Akun"

Bad:  
"Yuk, bergabung dan mulai petualangan membaca yang luar biasa!"

Better:  
"Buat Akun"

Bad:  
"Oops! Sepertinya ada sedikit masalah nih!"

Better:  
"Email atau kata sandi salah."

Bad:  
"Akun penerbit Anda sedang dalam proses perjalanan verifikasi."

Better:  
"Pendaftaran berhasil. Akun Anda menunggu persetujuan administrator."

Avoid repeating the page title in a badge, subtitle, and introductory card.

## 6.3 Restrained interface feedback

Use:

- Field-level validation.
- Clear inline messages.
- Appropriate confirmation states.
- Relevant status information.

Do not:

- Wrap every status in a colorful capsule.
- Display a toast and an alert with identical text.
- Create a modal for every minor form error.
- Add decorative success animations without functional value.

Exception: a modal or confirmation dialog may be used when required by the documented scenario or when it materially improves user understanding.

## 6.4 Content quality

No filler text such as:

- Lorem ipsum.
- "Your amazing experience starts here."
- "Empowering your digital journey."
- "Revolutionize your reading experience."

Use realistic, context-appropriate mock content.

Create a complete buyer registration design.

## 8.1 Main frame

Recommended frame name:

`F01 / Buyer / Register / Default`

Fields required by the use case:

- Nama lengkap.
- Email.
- Kata sandi.
- Nomor HP.

Primary action:

**Daftar**

Secondary navigation:

**Sudah punya akun? Masuk**

Additional UI:

- Proper field labels.
- Clear focus states.
- Password visibility control where appropriate.
- Required-field indicators only where useful.
- Validation feedback near corresponding fields.

Do not add unapproved registration fields.

Do not introduce mandatory birth dates, addresses, identity cards, or additional verification steps without documented requirements.

## 8.2 Layout expectations

The form should:

- Have a comfortable reading width.
- Avoid excessively wide input fields on desktop.
- Use sensible vertical spacing.
- Clearly identify the primary action.
- Support keyboard and screen-reader-friendly labeling at the design-specification level.
- Fit mobile widths without horizontal overflow.

Avoid unnecessary double-column form layouts when a single column is more usable.

## 8.3 Required visual states

Create design variants or clearly organized state frames for:

**Default**

- Registration form before submission.

**Field Validation**

- Missing required fields.
- Invalid email format.
- Incomplete information.

**Duplicate Email**

- Email has already been registered.
- Display an appropriate error.
- Preserve unaffected input values.

**Successful Registration**

- Explain that registration succeeded.
- Provide a clear path to the buyer login screen.
