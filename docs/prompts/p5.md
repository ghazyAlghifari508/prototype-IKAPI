## 2. Target Blade

Contoh (ubah nama mengikuti blueprint P01):

```
resources/views/buyer/home.blade.php
resources/views/buyer/catalog/index.blade.php
resources/views/buyer/books/show.blade.php
resources/views/buyer/books/preview.blade.php
resources/views/components/ikapi/book-card.blade.php
resources/js/ikapi/catalog/...
```

Gunakan `layouts.public`, named routes dan parameter buku yang diverifikasi. Nama route contoh: `home`, `books.index`, [`books.show`](http://books.show), `books.preview`. Jangan hardcode ID buku contoh atau membuat semua card menuju buku pertama. Route invalid/ID tak ada harus menampilkan not-found yang layak, bukan fallback palsu.

## 3. Data dan rendering

- Buat satu fixture awal untuk metadata/daftar buku, kategori, penulis, penerbit, harga, rating, sampul, preview, dan rekomendasi **berdasarkan data yang benar-benar ada dalam prototype**. Jangan inventaris data melebihi referensi hanya untuk mengisi tampilan.
- Blade render initial markup; JS dapat menangani filter/sort/live search/card state; jaga ID/slug konsisten. Jika katalog dan detail menggunakan buku yang sama, sumber data harus sama.
- Pertahankan status keranjang dan Wishlist hanya jika memang sudah ada; integrasi lengkap checkout dilakukan P06.
- Hindari render data via `innerHTML` tanpa escaping pada input pengguna; Blade output escaping default harus tetap aman. Jangan membuat server persistence.

## 4. Fidelity ketat

- Beranda: semua hero/banner asli, ilustrasi, sections kategori, buku unggulan, card, carousel, CTA, whitespace, footer. Jika banner prototype adalah gambar, jangan mengubahnya menjadi hero baru atau menambahkan CTA dekoratif.
- Katalog: grid card, filters, search, sort, pagination/load more, image ratio, stock/demo labels dan horizontal scroll mobile. Label panjang, jumlah item, dan responsive wrapping harus sama dengan baseline.
- Detail Buku: cover, metadata, purchase CTA, tabs/description, preview, reviews, related books. Jangan membenahi copy/desain yang tidak diminta.
- Preview Buku: asset sample dan reading view sesuai source; jangan memanggil PDF atau endpoint sungguhan.
- Ikuti P02 di `1440×900`, `1366×768`, `768×1024`, `390×844`, `320×700` ketika relevan. CSS/preflight regressions harus dilokalisasi, bukan menimpa global style.

## 5. Interaction contract

Buat tabel per interaksi: source HTML action → Blade route/JS action → expected state → test. Verifikasi minimal:

- Home → Catalog → Book Detail → Preview → Back.
- Search/filter/sort, clear filter, no-result message, pagination/load-more bila ada.
- Open book from recommendation and return properly.
- Navigasi cart/login dari header tidak harus final sebelum P06; siapkan kontrak route yang jelas tanpa broken `href="#"` palsu.
- Link yang merupakan scroll-to-section di HTML dipertahankan sebagai in-page anchor jika memang benar.

Prioritaskan bukti **font, cover crop, spacing, nav, card dimensions, line wrapping, viewport overflow**. Perbaiki regresi saat itu juga; full cross-site QA tetap P11.

### Acceptance criteria

- Semua empat halaman/subflow ada dan direct URL + reload bekerja.
- Konten/urutan dan gambar sesuai HTML acuan.
- Search/filter/sort/preview berfungsi sesuai prototype.
- Tidak ada asset 404, JS error terkait migrasi, atau unapproved visual diff.
- Layout dipakai bersama tanpa menggandakan header/footer.
- Dummy fixtures punya satu sumber dan tidak memerlukan database.
