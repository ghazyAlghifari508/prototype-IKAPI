# P01 — Audit lengkap dan blueprint migrasi HTML → Blade

## Kontrak global wajib (berlaku untuk prompt ini)

- **Repository:** `ghazyAlghifari508/prototype-IKAPI`; **branch target yang diminta pemilik:** `prototype`. Pada inspeksi GitHub 18 November 2026, branch remote `prototype` belum ditemukan; `prototype-only` masih tersedia. Di lingkungan agent, **verifikasi dulu branch aktif, remote, commit, dan versi prototype final**. Jika `prototype` hanya ada secara lokal, bekerja pada branch lokal itu; jangan otomatis beralih ke `main` (menggunakan React/Inertia), jangan melakukan reset/checkout destruktif, dan jangan menebak sumber. Bila source belum terverifikasi, laporkan blocker sebelum mengubah kode.
- **Source of truth visual:** HTML asli pada `docs/design/prototype-copy/{user,penerbit,admin}` dan aset `docs/design/assets/`, termasuk state interaktifnya. **JANGAN hapus, pindah, ubah, format ulang, atau overwrite HTML asli dan aset referensi.** File Blade dan aset runtime dibuat di lokasi aplikasi yang sesuai.
- **Stack tujuan:** Laravel 13, Blade, Tailwind CSS 4 via Vite, JavaScript vanilla untuk interaksi; gunakan Alpine.js yang sudah ada hanya bila benar-benar bermanfaat dan konsisten. Tidak menggunakan Bootstrap, React, Vue, Inertia, Livewire, template dashboard baru, atau library UI yang mengubah tampilan. Tailwind adalah styling utama; sedikit CSS khusus diperbolehkan bila dibutuhkan demi fidelity (misalnya connector atau scrollbar).
- **Batas scope:** FRONTEND-ONLY + dummy fixtures/state. Tidak mengintegrasikan database, Eloquent business queries, auth nyata, middleware role nyata, Midtrans, webhook, email/OTP, PDF server, API bisnis, atau transaksi sungguhan. Interaksi yang disimulasi wajib diberi batasan jelas. Jangan menjalankan migrate/seed/drop/truncate atau memanipulasi data produksi.
- **Preservasi:** tidak mendesain ulang halaman, mengubah copy, merapikan spacing menurut selera, mengganti gambar, menciptakan statistik palsu baru, atau menghidupkan fitur yang telah dibatalkan. Jika prototype punya cacat yang sudah ada, catat sebagai baseline defect dan minta pekerjaan terpisah; jangan memperbaikinya diam-diam dalam migrasi.
- **Proses:** baca [`AGENTS.md`/aturan](http://AGENTS.md/aturan) repo jika tersedia, periksa `GRAPH_[REPORT.md](http://REPORT.md)` bila tersedia, inspeksi struktur/dependensi dan working tree sebelum edit. Perubahan harus minimal, dapat ditelusuri dari HTML sumber ke Blade target, tanpa duplikasi masif. **Tidak commit/push/merge/deploy/publish** tanpa izin.
- **Bukti:** bedakan *belum diuji*, *lulus*, *gagal*, dan *blocked*. Kriteria “100% mirip” berarti **tidak ada perbedaan visual/fungsional yang belum dijelaskan atau disetujui** setelah pengujian pada browser/viewport/state yang sama; jangan mengklaim kesamaan matematis 100% hanya dari perasaan.
- **Handoff:** tiap fase menyimpan laporan di `docs/migration/` (folder baru terpisah dari prototype) berisi sumber yang diperiksa, perubahan, route/component/data contract, hasil validasi, isu tersisa, dan petunjuk fase berikutnya. Gunakan file laporan yang konsisten; tidak boleh menghapus laporan fase sebelumnya.

## 3. Audit perilaku dan data

- Telusuri dari Beranda ke Katalog → Detail Buku → Keranjang → Checkout → Riwayat → Perpustakaan → Reader; periksa state yang berpindah halaman.
- Telusuri Login Demo / Register / role Buyer &amp; Publisher / pengajuan Penerbit / status / dashboard / approval Admin. Ini hanya simulasi, **bukan security model**.
- Telusuri Komunitas: direktori → profil → keanggotaan → ruang diskusi → topik → komentar bertingkat → balas komentar; verifikasi `parentReplyId`, laporan moderator, dan akses tombol Buat Topik.
- Telusuri Admin: pengelolaan pengguna, katalog, moderasi ulasan, komunitas, diskusi, pencairan, monitoring.
- Audit `localStorage`, `sessionStorage`, global JS variables, inline `onclick`, `querySelector` ID, form actions, query parameters, `window.location`, anchor `href`, script loading order, event handlers, JS `innerHTML`, data seed, demo guards, URL eksternal, loading/error/empty states.
- Identifikasi koneksi antarhalaman yang sebenarnya tidak ada dalam prototype; **jangan mengarangnya**. Usulkan mock contracts yang jelas bila dibutuhkan nanti.

## 4. Audit styling dan responsive

- Inventaris `tailwind.config` inline dari CDN, utility yang digunakan, variabel `:root`, font DM Sans/Plus Jakarta, Material Symbols, CSS khusus, dynamic class strings, arbitrary values, custom breakpoints, dark mode bila benar-benar ada, overlay z-index, sticky/fixed header, mobile nav, image crop.
- Identifikasi perbedaan antara HTML desktop dan mobile, termasuk halaman mobile yang hanya redirect. Rencanakan apakah satu responsive Blade masuk akal; jangan menyatakan satu layout dapat mengganti dua desain sebelum membandingkannya.
- Klasifikasikan bagian UI reusable: public header/footer, auth shell, publisher/admin sidebar/topbar, book card, komunitas, status, table, drawer, modal, notice, pagination, chatbot. Jangan menjadikan setiap `div` komponen.

## 5. Arsitektur usulan dan rute

Buat pohon `resources/views/{layouts,components,partials,buyer,publisher,admin,auth-demo}`, `resources/css/ikapi/`, `resources/js/ikapi/`, lokasi fixture data dan `public/assets/ikapi/` sebagai **proposal**, disesuaikan source aktual. Tentukan aturan:

- named route, slug/ID, not-found valid, direct URL refresh, browser Back;
- satu owner untuk setiap dummy fixture + persistensi demo;
- shared component dengan variasi jelas, bukan CSS global yang merusak halaman;
- assets yang disalin untuk runtime, HTML asli tetap disimpan;
- frontend-only routes mengembalikan Blade, tanpa auth/backend bisnis.
