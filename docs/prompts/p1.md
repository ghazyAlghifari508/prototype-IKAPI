### Floating sidebar

Sidebar harus:

- Berbentuk independent rounded card.
- Mempunyai gutter dari sisi viewport.
- Tidak menempel pada dinding website.
- Tidak menjadi full-height app sidebar seperti admin dashboard.

- Menampilkan active navigation state yang jelas.

- Max content width mengikuti Katalog/Profil final, sekitar 1320–1360px jika belum ada token final.

- Konten utama mengisi ruang yang tersisa.
- Gap antara sidebar dan konten sekitar 24px.

Nilai tersebut merupakan kandidat, bukan ukuran mutlak.

Prioritaskan token/container yang sudah digunakan halaman Profil Saya final.

# 13. REVIEW HISTORY — DATA RULES

Ini sangat penting.

Halaman Detail Buku sebelumnya memiliki contoh \*\*Ulasan Pembaca\*\* dari beberapa nama pengguna.

\*\*Jangan otomatis memasukkan semua ulasan publik tersebut ke Riwayat Ulasan akun yang sedang login.\*\*

Riwayat Ulasan hanya boleh menampilkan:

\*\*Ulasan yang dibuat oleh pengguna akun tersebut.\*\*

### Required inspection

Periksa:

- Review ID.
- Book ID.
- User ID.
- Rating.
- Review text.
- Created date.
- Updated date.
- Review ownership.

Gunakan sumber data yang benar-benar tersedia.

### Jika backend review belum tersedia

Boleh menggunakan client-side prototype state.

Namun:

- Gunakan data demo yang jelas.
- Jangan mencampur review pengguna dengan review publik.
- Jangan mengklaim review tersimpan di database.
- Jangan membuat review baru tanpa interaksi atau data existing.
- Jangan membuat rating agregat palsu.

### Recommended data model

\`\`\`js
{
  id: "review-id",
  bookId: "existing-book-id",
  userId: "current-user-id",
  rating: 4,
  comment: "Teks ulasan",
  createdAt: "ISO timestamp",
  updatedAt: "ISO timestamp"
}
\`\`\`

Gunakan ID dan struktur data canonical jika sudah ada.

Jangan membuat skema baru yang bertentangan dengan implementasi existing.

\*\*Hapus Ulasan?\*\*

"Ulasan untuk buku ini akan dihapus."

Actions:

- Batal.
- Hapus Ulasan.

### Behavior

- Batal tidak mengubah data.
- Konfirmasi menghapus review yang benar.
- Item hilang dari history.
- Jumlah ulasan diperbarui.
- Detail Buku tidak lagi menampilkan ulasan milik pengguna yang telah dihapus jika menggunakan shared data.
- Empty state muncul jika tidak ada ulasan tersisa.

Jangan menghapus seluruh rating/review buku dari pengguna lain.

### Security

Pengguna hanya boleh mengedit atau menghapus ulasannya sendiri.

Jika backend ada, ownership harus diverifikasi pada server.

Menyembunyikan tombol Edit/Hapus di frontend saja bukan authorization.
