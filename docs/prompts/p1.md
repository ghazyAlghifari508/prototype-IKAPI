## 4. URL CONTRACT

Gunakan halaman HTML terpisah dengan query parameter yang jelas.

Contoh:

```
komunitas_literasi_desktop.html

detail_komunitas_desktop.html
  ?komunitas=community-klub-buku

ruang_diskusi_komunitas_desktop.html
  ?komunitas=community-klub-buku

detail_topik_komunitas_desktop.html
  ?topik=TPC-101

balas_komentar_komunitas_desktop.html
  ?topik=TPC-101&balasan=RPL-201
```

Contoh ID tidak boleh dijadikan hardcoded destination.

### Required

- Gunakan ID aktual.
- Gunakan `URLSearchParams` atau mekanisme URL existing.
- Gunakan encoding parameter yang aman.
- Validasi setiap parameter.
- Tampilkan not-found jika entitas tidak ditemukan.
- Jangan fallback ke komunitas/topik/komentar pertama.
- Gunakan link semantik untuk navigasi antardokumen.
- Browser Back dan Forward harus sesuai riwayat pengguna.
- Tombol Kembali dari Reply harus kembali ke Detail Topik yang benar.
- Kembali dari Detail Topik harus kembali ke Ruang Diskusi komunitas yang benar.
- Kembali dari Ruang Diskusi harus menuju Profil Komunitas terkait.

### Backward compatibility

HTML existing sudah mendukung:

- `?komunitas=`
- `?topik=`

Jangan biarkan tautan lama langsung rusak.

Implementasikan redirect/compatibility routing untuk URL lama jika diperlukan dan memungkinkan.

Jangan menggunakan JavaScript yang diam-diam membuka konten lain ketika ID tidak ditemukan.

## 5. SHARED DATA LAYER

Prototype saat ini menggunakan localStorage.

Key yang diketahui:

```
ikapi_communities_demo
ikapi_buyer_session_demo
ikapi_community_memberships_demo
ikapi_community_topics_demo
ikapi_community_replies_demo
ikapi_discussion_reports_demo
```

Periksa key aktual sebelum mengedit.

### Critical rules

- Pertahankan existing storage keys.
- Pertahankan entity IDs.
- Pertahankan parentReplyId.
- Pertahankan report targets.
- Pertahankan timestamps.
- Pertahankan member relationships.
- Pertahankan edited/removed states.
- Jangan menghapus data yang sudah dibuat pengguna.
- Jangan reset localStorage.
- Jangan menjalankan ulang seed yang menimpa data existing.
- Jangan membuat storage baru terpisah untuk setiap halaman.

### Data consistency

Misalnya pengguna:

1. Bergabung dari halaman Profil.
2. Membuka Ruang Diskusi.
3. Membuat Topik.
4. Membuka Detail Topik.
5. Menulis balasan.

Semua halaman harus melihat data dari sumber yang sama.

Jika Admin mengubah status topik atau komunitas, tampilan pembeli harus membaca perubahan tersebut sesuai kemampuan sistem prototype.

### Important: browser origin

Jangan mengasumsikan localStorage pada berbagai URL `file://` pasti memiliki perilaku penyimpanan lintas-file yang konsisten.

Audit cara prototype dijalankan dan pastikan pengujian lintas halaman menggunakan origin HTTP yang sama bila memang membutuhkan browser storage bersama.

Dokumentasikan keterbatasan environment lokal.

Jangan mengklaim sinkronisasi backend/multi-user dari data browser.
