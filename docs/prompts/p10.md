# 1. ROLE &amp; PRIMARY OBJECTIVE

Act as a Senior Product Designer, Senior UI/UX Designer, Digital Reading Experience Designer, Accessibility Specialist, and Design Systems Engineer.

You are continuing the existing IKAPI Jawa Barat e-book marketplace design project.

Your responsibility is to design the complete prototype for:

1. **UC-18 — Membaca E-Book (Buku Saya)**
2. **UC-19 — Menambahkan Bookmark**

These use cases describe the reading experience after the user has purchased a digital book.

The design must demonstrate:

- Opening an owned e-book.
- Verifying book access conceptually.
- Displaying the e-book reader.
- Navigating between pages.
- Continuing from the last-read page.
- Automatically preserving reading position conceptually.
- Adding a bookmark to the current page.
- Recognizing a page that is already bookmarked.
- Handling unauthorized access.

The reader must feel like a credible digital-book reading product.

**Do not create a generic document editor, PDF editor, or SaaS dashboard.**

**This is a design prototype task, not an application implementation task.**

Do not implement real PDF streaming, license validation, database persistence, or document security infrastructure.

- The buyer has purchased the e-book.
- The buyer opens the book from their personal library.
- The system verifies the user's book license.
- The reader displays the book.
- The reader resumes at the last-read page.

# 5. DESIGN PHILOSOPHY — READING FIRST

The reader must prioritize the content of the book.

Unlike the marketplace homepage, the reading interface needs minimal distractions.

## Primary goals

1. Comfortable reading.
2. Clear page navigation.
3. Easy return to the library.
4. Accurate reading progress.
5. Discoverable bookmarking.
6. Minimal visual noise.

## Desired character

- Calm.
- Focused.
- Readable.
- Predictable.
- Lightweight.
- Editorial.
- Consistent with IKAPI.

Avoid:

- A dashboard-style interface.
- Promotional banners.
- Excessive information cards.
- Large decorative illustrations.
- Constant floating actions.
- Too many sidebars.
- Giant shadows.
- Overly colorful navigation.
- Unnecessary status badges.
- Decorative dots.
- Repeated toolbar labels.

The book content should occupy most of the user's attention.

# 7. STRICT ANTI-AI-SLOP RULES

These requirements apply to all F08 screens.

## 7.1 No decorative noise

Do not create:

- Random dots.
- Floating geometric shapes.
- Decorative book characters.
- Unnecessary gradients.
- Glowing controls.
- Oversized badges.
- Pills around every label.
- Giant shadows.
- Fake progress animations.
- Unnecessary feature cards.
- Decorative status panels.
- Multiple redundant toolbars.
- Excessive icons.
- Huge blank spaces caused by poor layout.
- Arbitrary background patterns.

## 7.2 No text-background slop

Ordinary titles, labels, page numbers, and helper text must not receive independent white-background frames without a functional reason.

Inspect parent containers and fills.

The reader page may naturally have a white document surface; this does not justify wrapping every toolbar label or page number in its own white card.

## 7.3 No duplicate information

Avoid displaying:

- Current page in three different places.
- Book title repeatedly in header, sidebar, and floating panel.
- Multiple bookmark-success messages.
- Repeated reading-progress labels.
- The same instruction in the toolbar and a large helper card.

Present information where it is useful.

## 7.4 Natural Indonesian copywriting

Use concise, professional text.

Bad:  
"Selamat datang di petualangan membaca yang tak terlupakan!"

Better:  
"Baca Buku"

Bad:  
"Yeay! Halaman favoritmu berhasil disimpan!"

Better:  
"Bookmark berhasil ditambahkan."

Bad:  
"Oops! Kamu belum punya tiket untuk menjelajahi buku ini."

Better:  
"Akses ditolak. Anda belum memiliki lisensi e-book ini."

Bad:  
"Terakhir kali kamu menjelajah sampai halaman 12!"

Better:  
"Lanjutkan dari halaman 12"

Bad:  
"Halaman ini sudah jadi bagian dari koleksi penanda ajaibmu!"

Better:  
"Halaman ini sudah ditandai sebelumnya."

Do not create unnecessary introduction panels or onboarding messages.

# 12. AUTO-RESUME — LAST-READ POSITION

UC-18 specifically requires the reader to reopen at the last-read position.

This is a critical requirement.

## 12.1 Required conceptual states

Create:

1. Initial reading state.
2. Reader after page navigation.
3. Reader reopened at the previous last-read page.

Example:

```
Open Book
    |
    v
Page 12
    |
    | Navigate
    v
Page 18
    |
    | Leave Reader
    v
Return to Library
    |
    | Reopen Same Book
    v

```

## 12.2 UI rules

The reader should not automatically return to page one when the demo is intended to demonstrate resume behavior.

A brief contextual indicator can be used if it genuinely helps users understand where they resumed.

For example:

"Lanjutkan dari halaman 18"

Do not create:

- Large welcome-back banners.
- Celebratory animations.
- Multiple duplicate reading-progress messages.
- A prominent progress dashboard unrelated to the reading task.

## 12.3 Save-position feedback

The specification describes automatically saving the user's last-read page.

Represent this behavior conceptually.

Do not require the user to press "Simpan Posisi" unless the specification supports it.

Avoid a persistent oversized save-progress indicator.

If an auto-save indicator is needed, make it subtle.

Do not claim actual database persistence.

# 13. UC-19 — ADD BOOKMARK

Create the bookmark interaction inside the e-reader.

Suggested state names:

- `F08 / Bookmark / Not Bookmarked`
- `F08 / Bookmark / Added`
- `F08 / Bookmark / Already Exists`

## 13.1 Default action

The reader provides a bookmark action for the active page.

Use a clear label or familiar icon with an accessible meaning.

Example:

**Bookmark**

or an appropriate bookmark icon with a clear accessible label.

## 13.2 Successful bookmark

When the buyer marks the current page:

- The state changes to reflect that the page is bookmarked.
- A concise confirmation appears if useful.

Suggested message:

"Bookmark berhasil ditambahkan."

Do not create a giant confirmation modal.

Do not use confetti or decorative success graphics.

## 13.3 Duplicate bookmark

The use case explicitly covers attempts to bookmark a page that has already been marked.

Represent:

"Halaman ini sudah ditandai sebelumnya."

Do not create duplicate bookmark entries for the same page in the conceptual design.

The existing bookmark state should remain consistent.

## 13.4 Optional bookmark access

A compact bookmark list or panel can be useful to demonstrate how the saved location is revisited.

However, UC-19 explicitly specifies **adding** a bookmark, not a complete bookmark-management system.

Do not implement extensive:

- Bookmark renaming.
- Bookmark folders.
- Bookmark sharing.
- Bookmark deletion workflows.
- Cross-device synchronization settings.
- Advanced annotation systems.

If a simple list is included, keep it proportional to the documented scope and clearly distinguish it as a supporting design decision.

# 14. LICENSE VERIFICATION &amp; ACCESS DENIED

UC-18 requires the system to verify e-book ownership before opening the reader.

The prototype must represent this boundary accurately.

## 14.1 Authorized state

A buyer with an active license can access the book content.

## 14.2 Unauthorized state

A buyer without valid entitlement cannot access the reading interface.

Create:

`F08 / Reader / Access Denied`

Suggested heading:

**Akses Buku Ditolak**

Suggested explanation:

"Anda belum memiliki lisensi e-book ini."

Appropriate action:

**Kembali ke Katalog**

Or return to another actual existing, relevant destination.

## 14.3 Security semantics

Do not show the full book content behind the denied-access state.

Do not display an active reader with a small warning badge when access is denied.

Do not imply that frontend-only access checks are secure.

Do not implement actual licensing logic.

The production system must enforce authorization through a trusted backend, but that implementation is outside this design task.

## 14.4 No original PDF download

The IKAPI product intends that purchased e-books are read within the application, not distributed as freely downloadable original PDFs.

Therefore:

- Do not introduce a download-original-PDF button.
- Do not introduce print-original-PDF controls as part of the default design.
- Do not create an obvious export-original-document interaction.
- Do not claim that hiding buttons prevents all copying, screenshots, or unauthorized distribution.

The design should communicate the intended product experience without making unsupported technical-security claims.

**Important distinction:** F07's invoice PDF download is allowed conceptually; this does not authorize downloading the e-book PDF.

# 15. RESPONSIVE READER EXPERIENCE

Create desktop and mobile reading experiences.

## 15.1 Desktop

Use the established desktop viewport convention.

The reading surface should:

- Have a comfortable maximum width.
- Avoid extremely long lines for reflowable demonstration content.
- Preserve page proportions for fixed-layout source pages.
- Avoid unnecessary empty side panels.
- Keep navigation accessible.

The reader may use a focused, centered document surface.

## 15.2 Mobile

Design mobile deliberately.

Do not shrink the desktop interface into an unusable miniature.

Prioritize:

- Readable content.
- Compact header.
- Accessible page navigation.
- Usable bookmark action.
- Appropriate screen margins.
- Minimal toolbar obstruction.
- No unexpected horizontal overflow of the surrounding UI.

For fixed-layout PDF pages, consider the need for zoom or controlled page scaling, but do not introduce complex gestures or controls unless they are necessary to demonstrate readability and supported by the prototype environment.

## 15.3 Controls

Mobile controls must not obscure text.

Avoid oversized floating toolbars.

Do not fill the screen with multiple action rows.

## 15.4 Edge cases

Review:

- Long book title.
- Long paragraphs.
- Dense pages.
- Wide illustrations.
- Last-page navigation.
- First-page navigation.
- Existing bookmark.
- Resume state.
- Unauthorized access.
- Different book-page proportions.
