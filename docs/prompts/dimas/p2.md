## 3. SPECIFICATION CONFLICT — PUBLISH DIRECTLY VS ADMIN REVIEW

UC-32 menyatakan penerbit dapat memilih:

- `Publish`, langsung tampil di katalog.
- `Unpublish/Draft`, disimpan sementara.

Namun dokumen arsitektur proyek juga menekankan kebutuhan pengawasan/moderasi katalog oleh administrator.

Ini merupakan perbedaan yang perlu ditangani secara eksplisit.

**Jangan diam-diam menambahkan approval admin ke UC-32**, karena akan mengubah perilaku Publish yang tertulis dalam skenario.

Sebaliknya, jangan menghilangkan kemungkinan moderasi katalog yang diperlukan oleh dokumen proyek.

Lakukan:

1. Identifikasi aturan publikasi dalam seluruh spesifikasi.
2. Verifikasi apakah ada keputusan tim yang lebih baru.
3. Gunakan kontrak publikasi yang sudah disepakati jika tersedia.
4. Jika belum ada keputusan, dokumentasikan konflik dan gunakan desain status yang tidak sulit diperluas.
5. Jangan membuat workflow review/approval admin milik Lydia sekarang.
6. Jangan mengklaim proses moderasi katalog selesai.

Implementasikan perilaku yang dapat dibuktikan sesuai ketentuan yang berlaku dalam proyek.

## 4. DATA CONTRACT

Gunakan model buku kanonis bersama.

```
Publisher
    |
    v
Book
    |
    +-- Title
    +-- Author
    +-- Category
    +-- Synopsis
    +-- Page Count
    +-- Original Price
    +-- Discount Percentage
    +-- Publication Status
    |
    +-- Cover Asset
    |
    +-- Original E-book PDF
```

Ini kontrak konseptual, bukan perintah membuat kolom/model baru apabila sudah ada.

### Important rules

- Setiap buku memiliki publisher owner.
- Gunakan foreign key yang benar.
- Gunakan kategori bersama, bukan tabel kategori versi Dimas.
- Jangan membuat model Book kedua untuk Vayola/Aprila.
- Pertahankan referential integrity.
- Periksa pengaruh soft-delete/takedown terhadap transaksi historis.
- Jangan menghapus buku yang sudah pernah dibeli secara destruktif tanpa aturan.
- Gunakan migration baru dan aman.
- Jangan mengubah harga order yang sudah tercatat ketika harga katalog berubah.

## 5. PRICE &amp; DISCOUNT LOGIC

Harga e-book menggunakan Rupiah.

Gunakan representasi nominal integer sesuai kontrak transaksi.

Jangan menghitung nilai uang dengan floating point.

Diskon promo:

- Harus memiliki validasi.
- Tidak boleh negatif.
- Tidak boleh melampaui batas persen yang masuk akal.
- Tidak boleh membuat harga jual akhir negatif.
- Gunakan aturan pembulatan Rupiah yang konsisten.
- Tidak boleh otomatis berarti voucher global.

### Example

```
Harga Asli      Rp 80.000
Diskon Promo         10%
-------------------------
Harga setelah diskon
                 Rp 72.000
```

Contoh ini hanya ilustrasi perhitungan.

Jangan hardcode buku, harga, atau diskon tersebut ke database produksi.

### Order snapshot boundary

Ketika pembeli membuat order, Ghazy harus menyimpan snapshot harga yang benar.

Dimas hanya menyediakan harga katalog yang berlaku.

Jangan mengubah harga transaksi lama saat penerbit memperbarui diskon.

Jangan membuat sistem pembayaran atau komisi.

## 6. BOOK COVER HANDLING

Sampul buku adalah aset visual katalog.

Requirements:

- Validasi server-side terhadap file gambar.
- File type yang didukung sesuai kebijakan yang benar.
- Ukuran maksimum yang wajar dan terdokumentasi.
- Filename aman dan dibuat sistem.
- Aspect ratio tidak dirusak.

- Tidak menampilkan random stock photos sebagai cover buku.
- Tidak mengarang gambar buku dari judul.

Preview foto yang dipilih sebelum save diperbolehkan.

Jangan membuat pengolahan gambar kompleks bila kemampuan existing cukup.

## 7. ORIGINAL PDF SECURITY

**PDF asli harus privat.**

Ini kebutuhan arsitektur IKAPI, bukan sekadar preferensi desain.

### Storage

Gunakan:

- Laravel Storage abstraction.
- Private disk.
- Backend-managed file paths.
- Local private storage atau R2/S3-compatible private storage sesuai konfigurasi existing.
- File identifiers yang tidak berasal langsung dari filename pengguna.

Dilarang:

- Menyimpan original PDF di `public/storage` yang terbuka.
- Membuat link download permanen ke PDF asli.
- Mengembalikan storage path mentah kepada pembeli.
- Menjadikan asset URL publik sebagai sumber konten reader.
- Menggunakan nama file user sebagai path tepercaya.
- Menaruh PDF sebagai bundled frontend asset.

### PDF integrity

UC-32 secara eksplisit meminta penolakan file PDF yang corrupt atau bukan PDF valid.

Jangan memeriksa ekstensi `.pdf` saja.

Gunakan kombinasi:

- Laravel upload validation.
- MIME/content checks.
- Pemeriksaan struktur/keterbacaan PDF menggunakan tooling yang kompatibel jika benar-benar diperlukan.
- File size limits.
- Penanganan file error.
- Safe cleanup pada kegagalan.

Jika memerlukan PDF parser/tool tambahan, periksa kompatibilitas, sumber resmi, kebutuhan deployment, dan keamanan pemrosesan file terlebih dahulu.

**Jangan pernah mengeksekusi konten dari file upload.**

Gunakan resource limits serta pemrosesan yang aman untuk berkas yang tidak dipercaya.

### Failure consistency

Jika file validasi gagal:

- Buku tidak dipublikasikan.
- Data tidak tersimpan parsial.
- File gagal tidak ditinggalkan sebagai aset publik.
- Penerbit melihat error yang jelas.
- Data form non-file tidak hilang tanpa alasan.

Jika upload valid tetapi operasi database gagal:

- Bersihkan file baru yang belum menjadi referensi sah.
- Pertahankan file lama jika sedang melakukan update.

Database transaction tidak otomatis me-rollback filesystem. Tangani keduanya dengan benar.

Contoh:

```

          |

          v
```

- Mengedit buku penerbit B.

- Mengubah publication status penerbit B.
- Mengakses original PDF penerbit B hanya dengan ID.

Gunakan policy backend, bukan sekadar frontend role checks.
