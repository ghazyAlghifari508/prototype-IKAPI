## 4. DEFINISI METRIK WAJIB

### A. Omzet Penjualan

Omzet harus berasal dari transaksi penjualan yang sah.

Gunakan canonical verified paid state dari Ghazy.

Jangan menjumlahkan:

- Cart.
- Pending order.
- Failed payment.
- Expired order.
- Cancelled order.
- Duplicate payment attempts.

Definisikan dengan jelas apakah nilai merupakan gross sales yang sudah dibayar dan bagaimana refund diperlakukan menurut kebijakan tim.

Jangan menyebut omzet sebagai profit atau saldo tersedia.

### B. Pembayaran Berhasil

Tentukan apakah ringkasan menampilkan:

- Jumlah transaksi berhasil.
- Nominal total transaksi berhasil.
- Proporsi berhasil dibanding transaksi relevan.

Minimal tampilkan metrik yang sesuai UC-43 dan bisa dibuktikan.

Jangan menampilkan success rate 98% jika tidak ada rumus dan data.

### C. Buku Aktif

Gunakan publication visibility contract dari Dimas/Lydia area katalog.

Buku draft/unpublished/taken down tidak boleh dihitung sebagai aktif apabila status kontrak menyatakannya tidak aktif.

Jangan menghitung total semua record Book lalu menyebutnya Buku Aktif.

### D. Jumlah Penerbit

Periksa definisi yang digunakan sistem:

- Semua publisher terdaftar, atau
- Penerbit yang disetujui/aktif.

Pilih yang konsisten dengan label UI dan kontrak resmi.

Jika menghitung hanya approved publisher, label harus mencerminkan hal tersebut.

Jangan mencampur User buyer dengan Publisher.

## 5. DATE &amp; PUBLISHER FILTER SEMANTICS

Kedua filter merupakan bagian inti UC-43.

### Date range

Gunakan interval yang jelas.

Contoh:

```
Dari    : 1 November 2026
Sampai  : 30 November 2026
```

Pastikan:

- Start date valid.
- End date valid.
- Start tidak melewati end.
- Timezone diperhitungkan.
- Payment timestamp yang benar digunakan.
- Interval inklusif sesuai kebutuhan bisnis.
- Filter tidak membuat missing records di akhir hari.

### Publisher filter

Gunakan Publisher ID/identifier sah di backend.

UI dapat mencari nama penerbit.

Jangan menggunakan nama sebagai satu-satunya identifier jika nama dapat sama atau berubah.

### Combined filter

```
Periode: November 2026
Penerbit: Penerbit A

Hasil:
Transaksi berhasil milik Penerbit A
dalam periode yang dipilih.
```

Jangan memperlakukan kedua filter sebagai OR condition yang mengabaikan salah satunya.

### Important: global snapshot vs period metrics

Buku aktif dan jumlah penerbit sering merupakan snapshot keadaan sekarang.

Omzet adalah metrik periode.

Jangan membuat filter periode seolah dapat menghitung jumlah buku aktif historis jika sistem tidak menyimpan sejarah status aktif pada tanggal tersebut.

Jika tidak ada historical state tracking:

- Jelaskan label metrik yang menunjukkan "saat ini".
- Biarkan data snapshot tetap berdasarkan kondisi terkini.
- Filter periode hanya diterapkan pada metrik yang memang memiliki dimensi waktu.

Jika filter penerbit diterapkan pada Buku Aktif, hitung hanya buku aktif penerbit tersebut.

Untuk jumlah penerbit saat satu penerbit dipilih, pastikan behavior dan label tidak membingungkan.

## 6. MULTI-PUBLISHER ACCOUNTING

Marketplace memiliki order yang bisa berisi lebih dari satu penerbit.

Contoh:

```
Order #1001 — Lunas

Buku A — Penerbit A — Rp 40.000
Buku B — Penerbit B — Rp 60.000

Global Order Total: Rp 100.000
```

### Monitoring global

Order tersebut tidak boleh dihitung dua kali hanya karena join ke dua OrderItems.

### Filter Penerbit A

Hasil penjualan penerbit A hanya mencakup nilai item miliknya, sesuai kontrak revenue allocation yang sah.

### Filter Penerbit B

Hasil penjualan penerbit B hanya mencakup bagian penerbit B.

Jangan:

- Menjumlahkan seluruh total order ketika filter publisher aktif.
- Mengalikan order total dengan jumlah item.
- Menggunakan total revenue publisher untuk menghitung jumlah transaksi global tanpa mendefinisikan unit perhitungan.

Jika biaya global seperti gateway fee tidak dapat dialokasikan secara sah per penerbit, jangan mengarang pembagiannya.

Bedakan gross sales item dan net earnings.

## 7. REPORTING QUERY ARCHITECTURE

Gunakan Eloquent/PostgreSQL aggregation.

```
Canonical Orders / Payments
             |
             v
      Verified Status Filter
             |
             v
      Period Filter
             |
             v
      Publisher Item Scope
             |
             v
        Aggregation
             |
       +-----+------+
       |            |
       v            v
    KPI Stats     Sales Chart
```

Pastikan:

- Query efisien.
- No N+1.
- Aggregate filters benar.
- Paid statuses konsisten.
- Correct grouping by date/month.
- Currency exact numeric.
- Zero-state benar.
- Database indexes bila benar-benar diperlukan.
- Tidak memuat semua transaksi ke PHP untuk dihitung manual jika SQL aggregation lebih tepat.

Jangan membuat data warehouse, analytics microservice, atau Redis requirement baru untuk UC-43.

### Source reuse

Jika Dimas sudah memiliki sales aggregation contract:

- Reuse definisi valid paid sale.
- Jangan otomatis reuse publisher-scoped query sebagai global total tanpa memahami perbedaannya.
