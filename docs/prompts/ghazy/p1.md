# 4. CANONICAL ORDER DOMAIN

Gunakan satu sistem order untuk semua pembeli dan penerbit.

Struktur konseptual:

```
Authenticated Buyer
         |
         v
        Cart — Falih
         |
         v
Checkout Validation
         |
         v
        Order
         |
         +-- Order Number
         +-- Buyer ID
         +-- Order Status
         +-- Pricing Snapshot
         +-- Created At
         |
         +-- OrderItem
         |       |
         |       +-- Book ID
         |       +-- Publisher ID
         |       +-- Book Title Snapshot
         |       +-- Quantity
         |       +-- Unit Price Snapshot
         |       +-- Discount Snapshot
         |       +-- Line Total
         |
         +-- OrderItem ...
```

Nama field hanyalah kontrak konseptual.

Gunakan schema aktual atau buat migration minimal yang konsisten dengan ERD dan tech stack.

## Model rules

- Order memiliki owner pembeli.
- Item mengacu pada buku yang valid.
- Item memiliki publisher association.
- Nominal snapshot disimpan agar tidak berubah setelah harga katalog berubah.
- Order number unik.
- Status disimpan di database.
- Timestamps benar.
- Gunakan foreign key dan constraints.
- Jangan menyalin seluruh data Book ke OrderItem tanpa kebutuhan.
- Jangan membuat satu order terpisah per penerbit jika desain bisnisnya satu checkout multi-penerbit.

# 9. IDEMPOTENCY &amp; CONCURRENCY

Pembeli dapat menekan `Konfirmasi Order` berulang kali.

Jangan membuat banyak order identik akibat:

- Double click.
- Browser retry.
- Request timeout.
- Refresh.
- Multiple tabs.

Gunakan strategi idempotency yang sesuai, misalnya request identifier dan unique constraint.

Jangan membuat global mutex in-memory sebagai satu-satunya pengaman.

## Database consistency

Pembuatan:

- Order header.
- Order items.
- Pricing snapshot.
- Hubungan dengan cart.

harus atomik.

Gunakan database transaction dengan benar.

Jika salah satu item gagal dibuat, jangan meninggalkan order setengah jadi.

Jika validasi ulang gagal, jangan membuat order.

Pertimbangkan row locking/optimistic concurrency sesuai pola Cart dan Order yang tersedia.

Jangan membuat order dua kali untuk satu konfirmasi yang sama.

---

# 10. CART CLEARING &amp; RESTORATION POLICY

Dokumen UC-13 dan UC-14 menyebut buku dikembalikan ke keranjang saat transaksi dibatalkan atau kedaluwarsa.

Karena itu, pembuatan order harus mempertahankan sumber informasi yang dibutuhkan untuk pemulihan item.

Jangan langsung menghapus semua cart items tanpa mekanisme restorasi yang benar.

Pilih strategi berdasarkan arsitektur Cart milik Falih:

- Menahan cart saat order pending.
- Menandai item sebagai bagian order pending.
- Mengosongkan cart dengan kemampuan restore yang idempotent.

Jangan membuat ketiganya sekaligus.

Pastikan:

- Cart tidak berisi duplikasi setelah restore.
- Buku yang sudah tidak dapat dibeli ditangani.
- Harga terbaru divalidasi saat checkout ulang.
- Order paid tidak dipulihkan sebagai cart pending.
- Pembatalan ganda tidak menggandakan item.

Implementasi transisi terminal lengkap dilakukan pada Prompt 04.

Prompt 01 harus menyiapkan kontrak dan state yang diperlukan.
