Gunakan file laporan yang konsisten; tidak boleh menghapus laporan fase sebelumnya.

## Peran dan tujuan

Migrate area **Portal Penerbit** from original HTML into Laravel Blade, use existing shared infrastructure P01–P07; no real publisher auth/approval/payout/backend. Preserve pixel-level layout and all existing demo workflows.

Inspect actual latest originals:

- `penerbit/dashboard_penerbit_desktop.html`
- `penerbit/kelola_buku_desktop.html`
- `penerbit/pesanan_masuk_desktop.html`
- `penerbit/pendapatan_dan_pencairan_desktop.html`
- `penerbit/ulasan_pembeli_desktop.html`

- `penerbit/invoice_penjualan_pdf_portal_penerbit.html`

- `penerbit/pendaftaran_penerbit_desktop.html`
- `penerbit/access-guard.js` plus mobile variants if present.

**Penting:** pada satu versi repo, login/pendaftaran portal adalah halaman *redirect* ke auth terpadu (`user/...?...role=publisher`), bukan page desain independen. Audit terlebih dahulu; pertahankan kontrak alias, jangan bikin duplikat form yang berbeda. `access-guard.js` hanya browser-side preview gate, bukan security.

## 2. View structure &amp; shell

Buat `resources/views/publisher/{dashboard,books,orders,finance,reviews,settings,...}` dengan partials untuk sidebar/topbar yang konsisten. Layout harus mempertahankan **banner geometris angled ungu, header toolbar, sidebar navigasi, dimensions, horizontal tables, overlay drawer, responsive scrim** seperti source. Jangan memakai generic admin dashboard template; jangan menyamakan link/sidebar Penerbit dan Admin secara buta.

## 3. Interaction requirements

- Dashboard charts/KPI dari fixture demo yang benar, tanpa memalsukan sinkronisasi server. Tabel dan ringkasan harus konsisten dengan data yang sama.
- Kelola Buku: list, filter/sort/search, detail/edit/create UI simulasi bila ada; cover preview, form validation, modal, status draft/published. Tidak mengupload file ke server/DB.
- Pesanan Masuk: order filters, tabs/status, action drawers, detail, status simulated; jangan menjalankan fulfillment sungguhan.
- Pendapatan &amp; Pencairan: saldo/summary/history, rekening UI, payout request/status simulasi. **Tidak memproses uang atau payment gateway**. Jangan menciptakan penghasilan/angka yang berbeda dari data source.
- Ulasan Pembeli: list/action/filter sesuai source; tidak memodifikasi komentar user sebenarnya.
- Pengaturan Profil: fields, tabs, edit state, validasi; role/profile dummy bersumber sama dengan auth demo (P06).
- Invoice: jika HTML aslinya adalah invoice-layout preview, tampilkan versi Blade/print preview sesuai source; jangan membangun PDF server atau endpoint baru. Preview/print browser hanya jika sesuai sumber.
- Approval state: incoming dari demo registrasi/approval P06/P09; tidak menjadi middleware auth produksi. Guard demo harus tidak membocorkan janji keamanan.

## 4. Data contract

Agar P09 dan P10 bisa menggunakan data yang sama, nyatakan ID/shape publisher, books, orders, reviews, income, bank accounts, withdrawal/status dari source aktual. Gunakan fixtures untuk initial state + browser store untuk demo mutations; jangan membuat dataset kedua hanya untuk dashboard. Simpan state melalui link/refresh pada origin HTTP yang sama; bila status tidak bisa disinkronkan lintas perangkat, tulis keterbatasan.

## 5. Fidelity and tests

Periksa font DM Sans, primary violet token, topbar/sidenav mobile toggling, action buttons, disabled states, responsive overflow of wide tables, modal/drawer focus, data rows, legends, number formatting, empty/error/loading states. Compare baseline vs Blade at desktop 1440/1366 + mobile 390/320. Test route navigation, dashboard→books→order→financial, login alias, publisher status denied/approved demo, modal actions, and page reload.

## 6. Handoff

`docs/migration/[p8-publisher.md](http://p8-publisher.md)` berisi source file map, route list, layout/partials, demo fixture contracts, screenshots/diffs, functional scenario matrix, edge cases and pending Admin integration. Keep HTML entirely untouched. Full browser QA remains P11.

### Completion gate

- Semua halaman unik Penerbit telah dikonversi; alias/redirect dipertahankan.
- Shell dan responsive rendering sesuai baseline.
- Semua interaksi demo yang tersedia berfungsi.
- Data yang berelasi konsisten; no auth/backend/DB/payout real.
- No broken assets, unknown routes, JS errors, or unexplained visual regressions.
