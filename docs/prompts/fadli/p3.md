# 7. BACKEND PROFILE UPDATE

## 7.1 Authentication &amp; identity

Gunakan authenticated user dari Laravel.

Jangan menerima `user_id` dari frontend sebagai penentu akun yang diedit.

Contoh prinsip:

```
Authenticated Session
         |
         v
Profile Update Request
         |
         v
Server-side Validation
         |
         v
Current Authenticated User
         |
         v
Database / Avatar Storage
```

Seorang pengguna tidak boleh dapat mengubah profil akun lain dengan memodifikasi request.

## 7.2 Validation

Validasi backend wajib meliputi:

- Nama wajib dan valid.
- Alamat sesuai aturan yang disepakati.
- Foto merupakan image yang diizinkan.
- Ukuran file tidak melewati batas.
- Data akun lain mengikuti rules existing.
- Email tetap unik apabila edit email didukung.
- Field yang tidak diizinkan tidak dapat diubah.

Jangan mengandalkan HTML `required` atau frontend file validation saja.

## 7.3 Mass-assignment safety

Hanya data yang memang boleh diubah yang masuk ke operasi update.

Jangan mengizinkan request mengubah:

- Role.
- Permission.
- Approval status.
- `email_verified_at`.
- Password hash.
- Account status.
- Admin flags.
- Publisher identity.
- Payout account.

Jangan melakukan `$user->fill($request->all())` tanpa validated field ownership.

## 7.4 Atomic update behavior

Pada validation failure:

- Data database tetap sama.
- Avatar lama tetap berlaku.
- Tidak ada informasi profil parsial yang tersimpan.
- User menerima pesan kesalahan yang sesuai.

Pada successful update:

- Data tersimpan.
- Avatar reference konsisten.
- UI menampilkan data terbaru.
- Session/auth props merefleksikan nilai terbaru.

Pertimbangkan konsistensi database dan file storage, karena transaksi database tidak secara otomatis me-rollback perubahan filesystem.

Jangan membuang avatar lama sebelum penggantinya benar-benar berhasil disimpan.

# 8. AVATAR UPLOAD — SECURITY &amp; FILE HANDLING

Ini bagian yang harus diimplementasikan dengan serius.

## 8.1 Accepted formats

Gunakan format image yang sesuai dengan kebutuhan proyek.

Prototype sebelumnya menggunakan:

- JPG/JPEG.
- PNG.
- WebP.

Namun UC-03 tidak menetapkan daftar format ataupun batas ukuran numerik secara eksplisit.

Periksa apakah aturan tersebut sudah disepakati dalam codebase atau dokumentasi terbaru.

Jika belum ditetapkan, gunakan kebijakan upload konservatif yang dapat dikonfigurasi dan dokumentasikan sebagai keputusan implementasi, bukan sebagai ketentuan resmi UC-03.

Jangan mengklaim "maksimal 2 MB" berasal dari dokumen UC apabila hanya berasal dari prototype sebelumnya.

## 8.2 Laravel validation

Gunakan validasi image resmi Laravel.

Pastikan:

- File benar-benar gambar.
- MIME/content validation dilakukan.
- Ukuran maksimum ditegakkan server-side.
- Ekstensi tidak menjadi satu-satunya sumber validasi.
- SVG tidak diizinkan tanpa kebutuhan dan perlindungan khusus.
- File executable tidak dapat diakses sebagai script.

Jangan hanya memeriksa nama file di frontend.

## 8.3 Filename &amp; storage

Gunakan nama file yang dihasilkan sistem.

Jangan gunakan filename asli pengguna sebagai path tepercaya.

Gunakan Laravel Storage API dan disk yang sesuai.

Jika menggunakan public avatar storage:

- Pastikan hanya aset profil yang memang boleh diakses melalui URL tersebut.
- Gunakan path yang tidak mudah berbenturan.
- Pastikan konfigurasi URL/storage benar.
- Pastikan tidak ada eksekusi script pada direktori upload.

Jangan membuat URL file dari input pengguna secara langsung.

## 8.4 Image handling

Jika proyek mempunyai utilitas image processing yang sudah tersedia, gunakan seperlunya.

Jangan menambahkan library besar hanya untuk menghasilkan avatar 1:1 jika CSS crop sudah cukup untuk kebutuhan UI.

Preserve aspect ratio.

Hindari stretching.

Gunakan fallback avatar yang konsisten bila pengguna belum mengunggah foto.

Jangan menggunakan random stock portrait sebagai foto default.

## 8.5 Replacing avatar

Alur:

```
Existing Avatar
      |
      v
Choose New File
      |
      v
Validate File
      |
   +-- Invalid
   |      |
   |      v
   |   Keep Existing Avatar
   |
   +-- Valid
          |
          v
      Save Replacement
          |
          v
    Update Avatar Reference
          |
          v
    Retire Old Avatar Safely
```

Jangan menghapus avatar default bersama atau file milik user lain.

Jika proses simpan baru gagal, avatar lama harus tetap valid.

Jangan meninggalkan referensi database menuju file yang tidak ada.
