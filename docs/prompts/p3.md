## 1. Inspeksi dan fondasi

- Pastikan branch `prototype` yang benar, PHP/Composer/Node kompatibel, Blade dan Vite berfungsi, `routes/web.php` tidak memakai auth Breeze; hindari migrate/seed/database.
- Inspeksi sumber `resources/css/app.css`, `resources/js/app.js`, `package.json`, `vite.config.*`; jangan mengganti dependency bila sudah sesuai. Retain vanilla JS untuk interaksi; Alpine.js opsional bila sudah dipakai, bukan wajib rewrite semua JS.
- Setup route dan navigation helper yang reusable, tetapi **jangan sekaligus membuat seluruh bisnis/halaman final**. Route untuk page belum diimplementasikan harus tidak memberi kesan sudah selesai; implementasikan bertahap.
- Pastikan local `.env` dev dapat render Blade tanpa tabel DB untuk session/cache/queue; dokumentasikan contoh konfigurasi frontend-only tanpa mengubah secret developer. Jangan menjalankan `composer run setup` bila itu menjalankan `migrate --seed`.

## 2. Tailwind 4 migration engine

Prototype banyak menggunakan Tailwind CDN + `tailwind.config` JavaScript di dalam HTML. Target adalah Tailwind v4 via Vite; **jangan** menyalin `<script src="[https://cdn.tailwindcss.com](https://cdn.tailwindcss.com)">` ke Blade.

- Bentuk design-token mapping dari P01/P02. Bawa warna contoh `#673DE6`, `#5025D1`, `#2F1C6A`, teks `#222225`, muted `#62636B`, border `#E5E7EB`, DM Sans, radius, breakpoints **sesuai source yang nyata**, bukan membuat sistem desain baru.
- Gunakan konfigurasi CSS-first `@import 'tailwindcss'`, `@theme`, `@source` sesuai Tailwind v4 dan source Blade/JS yang sebenarnya. Konfigurasi JS lama **tidak otomatis dibaca** oleh v4. Verifikasi penggunaan `@tailwindcss/vite` dan `laravel-vite-plugin` versi yang dipasang.
- Audit utility lama: classes custom palette (`bg-primary`, `text-ink-body`, `border-border-subtle`), arbitrary values, responsive variants, shadows, animation, `line-clamp`, forms, dark modifiers bila ada, `group-open`, `peer` dan custom CSS.
- **Jangan rangkai Tailwind class secara runtime** seperti `'bg-'+color`; Tailwind source scanning tidak dapat mendeteksi fragmen. Pakai literal full classes, map yang eksplisit atau CSS var yang tepat. Hanya safelist dengan mekanisme v4 bila terbukti diperlukan; hindari membengkakkan CSS.
- Audit v4 Preflight CSS reset yang dapat mengubah heading, border, button, image, form dan spacing dibanding CDN; lakukan kompensasi terlokalisasi dengan bukti.
- CSS khusus minimal boleh digunakan untuk struktur yang memang ada di prototype (reader layout, thread connector, scrollbar, overlay, etc). Jangan migrasi besar-besaran ke custom stylesheet tanpa alasan.

## 3. Assets

- Inventaris seluruh `../../assets/...`, inline SVG, icon fonts, web fonts, CSS background image, dynamically loaded book covers, images from CDN.
- Copy runtime assets (keep originals untouched) to organized `public/assets/ikapi/...` or Vite-managed `resources/...` as appropriate; use `asset()` for public assets or Vite for source imports. Verify same file hashes, dimensions, alt text, object-fit and relative asset paths across pages.
- No renaming of image files to “clean up” without mapping. Preserve special illustration `komunitasil.png`, `notfoundil.png`, auth illustration, logos, event and book images.
- No fake replacement or stock images when asset missing; report missing asset.

## 4. Dummy infrastructure without backend

- Define a simple fixture format (JSON or PHP arrays) for book/community/order/users and a browser-side demo state API where necessary. **Do not copy fixtures into every Blade** or create DB tables.
- Store conventions for demo session/role and localStorage keys; existing keys should be honored or migrated non-destructively after investigation. Separate seeded initial data from mutable browser state.
- Add a small helper for URL ID validation and missing-content state in later pages; no custom routing engine.
