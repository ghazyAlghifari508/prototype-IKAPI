## 2. Improve Book Cover Presentation

The original AI-generated prototype used flat colored rectangles as covers.

The current prototype now uses real artwork, which is an improvement.

Do not regress to the original placeholder design.

However, the new layout still requires refinement.

### Required media behavior

- Preserve book artwork.
- Preserve readable title and author information contained in the cover.
- Use a consistent book-cover aspect ratio whenever practical.
- Avoid unwanted cropping that removes important artwork.
- Do not stretch covers to fit arbitrary boxes.
- Do not place new black title overlays over existing cover artwork unless that overlay is part of the original image asset.
- Do not add decorative gradients or pills over the covers.
- Do not replace the supplied covers with generated placeholders.
- Maintain clear visual spacing between adjacent covers.

The book should be the dominant element of the product tile.

### Preferred visual structure

```
┌─────────────────────┐
│                     │
│     BOOK COVER      │
│                     │
│                     │
└─────────────────────┘

Pride and Prejudice
Jane Austen

Rp 45.000

[ Tambah ke Keranjang ]
```

This is a hierarchy example.

Do not force a large outlined card around every product.

Use consistent media dimensions but allow titles and supporting information to have appropriate content-driven height.

## 3. Correct Product Information Hierarchy

The current product grid has improved compared with the first version, but its information can still be clearer.

Prioritize:

1. Cover image.
2. Title.
3. Author.
4. Price.
5. Purchase or detail action.

Publisher metadata may be included when useful.

Do not repeat publisher information in every card when it adds little value to the scanning experience.

Do not use decorative uppercase category labels above every product.

If category metadata is important, use it in filters, navigation, or appropriate details screens.

### Product action labels

Avoid ambiguous button text such as "Keranjang" when the actual action is adding an item.

Prefer:

"Tambah ke Keranjang"

If space is limited, explore a compact cart icon with a meaningful accessible label, while retaining clear interaction semantics.

Ensure a book title or image can lead toward book details when that flow exists.

Do not introduce actions that the prototype does not support without documenting their intended interaction.

when it leads to the catalog.

## 6. Events and Literacy Content

Events are a confirmed IKAPI requirement.

Keep event access available.

Inspect the relevant product specification before deciding which event information is actually supported.

### Current problems

- Event content is almost entirely plain text.
- The structure feels unfinished.
- There are no event-related visuals.
- The previous prototype used unnecessary colored event badges.
- The newer copy contains prototype disclaimers and unsupported announcements.

### Required changes

- Use actual event information if verified or explicitly supplied.
- If event data is only mock content, retain its status in the project data and presentation context.
- Do not portray fictitious events as real public announcements.
- Use available event imagery when appropriate.
- Inspect `community_reading.svg` and related event assets.
- Use clear content hierarchy: event title, date, location or format, and relevant action.
- Do not create colorful pill badges solely to distinguish event types.
- Do not force lengthy descriptions under every event.
- Do not manufacture dates or locations to make the cards look complete.

If there are no verified or approved demo events, preserve the navigation and provide a meaningful empty state in the event experience.

Avoid making an empty homepage section appear populated.

### Event preview concept

```
Agenda dan Kabar Literasi               Lihat Agenda

[EVENT IMAGE]     [EVENT IMAGE]     [NEWS IMAGE]
Event title       Event title       News title
Date / location   Date / format     Source / date
```

This is appropriate only when those records or approved demo records exist.

Do not add fabricated event cards to satisfy the example layout.

"Marketplace buku digital resmi penerbit anggota IKAPI Jawa Barat. Dikelola untuk distribusi buku daerah yang legal dan terukur."

### Visual requirements

- No unnecessary marketing paragraphs.
