# 1. ROLE &amp; OBJECTIVE

Act as a Senior Product Designer, Senior UI/UX Designer, E-Commerce UX Specialist, and Design Systems Engineer.

You are continuing the existing IKAPI Jawa Barat marketplace design project.

Your task is to design the complete F05 prototype covering:

1. \*\*UC-09 — Menambahkan ke Keranjang\*\*
2. \*\*UC-10 — Mengelola Keranjang\*\*
3. \*\*UC-11 — Membuat Order / Checkout\*\*

The expected result is a coherent shopping experience that connects existing book discovery screens to the future digital payment workflow.

This phase must demonstrate how a buyer:

- Opens a book detail page.
- Adds a book to their shopping cart.
- Receives appropriate confirmation.
- Opens the cart.
- Reviews cart contents.
- Changes quantities according to the documented use case.
- Removes items with confirmation.
- Reviews the resulting subtotal.
- Proceeds to checkout.
- Reviews the order summary.
- Confirms the order.
- Reaches the boundary of the payment process.

Use native editable design elements and reusable components.

\*\*This is a design prototype task, not a frontend or backend implementation task.\*\*

Do not implement real shopping cart storage, database transactions, order APIs, payment processing, or production business logic.

# 6. GLOBAL ANTI-AI-SLOP RULES

These requirements are mandatory for every frame.

## 6.1 Prohibited visual patterns

Do not create:

- Random decorative dots.
- Unnecessary pills and badges.
- Overly rounded containers.
- Giant card shadows.
- Floating glow effects.
- Arbitrary background gradients.
- Decorative blobs or circles.
- Unnecessary illustrations.
- Generic SaaS-style metric cards.
- Too many nested cards.
- Oversized headings on every page.
- Excessive icons.
- Unnecessary step indicators.
- Fake progress bars.
- Promotional stickers.
- Repeated status labels.
- Redundant summaries.
- Multiple visually competing primary actions.
- Fake loading effects.
- Gratuitous animation suggestions.

Use subtle borders and layout hierarchy instead of excessive elevation.

## 6.2 No card obsession

Not every piece of information requires its own card.

Examples:

Bad:
- One card for book cover.
- Another card for title.
- Another card for publisher.
- Another card for price.
- Another card for subtotal.
- Another card for each checkout instruction.

Better:
- One coherent cart item row.
- One readable order summary.
- One clear action area.

Use appropriate layouts, rows, dividers, and sections.

## 6.3 No duplicate information

Avoid:

- Repeating the same total three times.
- Repeating book titles in separate unnecessary summary blocks.
- Showing identical discount information in multiple places.
- Repeating the selected-item count in every section.
- Displaying the same confirmation message in a toast and a large banner.
- Explaining a button's function in multiple paragraphs.

Information should appear where the user needs it.

If a summary appears in both desktop and mobile design variants, that is not considered unnecessary duplication.

## 6.4 Natural Indonesian copywriting

Use concise, natural, professional Indonesian.

Examples:

Bad:
"Keranjang impianmu sudah siap menemani petualangan literasi!"

Better:
"Keranjang Belanja"

Bad:
"Yeay! Buku pilihanmu berhasil masuk ke keranjang!"

Better:
"Buku ditambahkan ke keranjang."

Bad:
"Ups, keranjangmu masih sepi nih!"

Better:
"Keranjang Anda kosong."

Bad:
"Tinggal satu langkah lagi menuju pengalaman membaca terbaik!"

Better:
"Periksa pesanan sebelum melanjutkan."

Bad:
"Waktunya menyelesaikan perjalanan belanjamu!"

Better:
"Konfirmasi Pesanan"

Do not add marketing slogans merely to fill space.

## 6.5 Purposeful components

Every component must have a legitimate purpose.

Use status indicators only when they clarify a real state.

Use dialogs only for meaningful decisions.

Use illustrations only when relevant.

Use one clear primary action per decision context.

# 8. IMPORTANT DOMAIN RULE — DIGITAL E-BOOK MARKETPLACE

IKAPI sells digital e-books.

The design must reflect that product type.

## 8.1 No physical delivery workflow

Do not create:

- Shipping-address forms.
- Courier selection.
- Shipping-cost calculations.
- Delivery tracking.
- Package weight fields.
- Physical stock selection.
- Cash-on-delivery options.
- Warehouse pickup options.

These are not part of the approved digital e-book purchase workflow.

Do not copy a generic physical-commerce checkout template.

## 8.2 Book quantity ambiguity

UC-10 explicitly describes changing item quantities.

However, quantity handling for a digitally licensed e-book may differ from physical goods.

\*\*This is a business-rule ambiguity.\*\*

Do not silently remove quantity controls from the design.

Also do not silently establish a permanent policy allowing unlimited purchases of the same e-book.

Required approach:

1. Represent the quantity-changing interaction described by UC-10.
2. Use realistic mock quantities to demonstrate the specified behavior.
3. Keep the quantity component reusable and easy to revise.
4. Avoid unsupported explanations such as gifting, bulk licensing, or multiple-reader ownership.
5. Record the unresolved question: whether each e-book license should be limited to one copy per buyer.
6. Do not create extra functionality based on that ambiguity.

The design must remain adaptable once the project team confirms the licensing policy.

# 9. UC-09 — ADD TO CART

Create the add-to-cart experience originating from the existing F04 Book Detail screen.

## 9.1 Entry point

Use the existing book detail action:

\*\*Tambah ke Keranjang\*\*

Do not rebuild the complete Book Detail page.

Inspect the existing button and its placement.

Make the smallest necessary adjustment to represent the cart interaction.

## 9.2 Required behavior

The documented main scenario is:

1. Buyer opens a book detail page.
2. Buyer selects "Tambah ke Keranjang".
3. The book is added to the cart.
4. The cart item count updates.
5. The interface displays success feedback.

Represent this flow through meaningful Figma states and prototype connections.

## 9.3 Add-to-cart feedback

Use restrained confirmation.

Recommended message:

\*\*Buku ditambahkan ke keranjang.\*\*

Do not use:
- Confetti.
- Giant checkmarks.
- Full-screen success illustrations.
- Large confirmation modals.
- Multiple identical alerts.
- Celebration animations.

A compact confirmation state is sufficient.

## 9.4 Cart counter

The cart navigation icon should communicate item count where appropriate.

Ensure:
- The count is readable.
- The count is not duplicated in unnecessary places.
- The icon matches the existing navigation component.
- The design works when the count increases.

If a compact count indicator is required, it is an acceptable functional exception to the anti-badge rule.

Do not use a decorative badge unrelated to the cart state.

## 9.5 Navigation choices

Allow the buyer to:

- Continue viewing the current book.
- Open the cart through the established navigation control.

Avoid introducing multiple competing CTAs in a large notification panel.

## 9.6 Content consistency

The added book must preserve its established identity:

- Same title.
- Same author.
- Same publisher.
- Same cover.
- Same price.

Do not invent a new title for the same book when it appears in the cart.

## 9.7 Recommended states

Create or update:

- Add-to-cart default action.
- Add-to-cart successful feedback.
- Updated cart count.

Do not generate unnecessary full-page variants for trivial hover states.

# 21. UX QUALITY REQUIREMENTS

## 21.1 Clear task completion

A buyer should understand what happens next without reading long instructions.

Avoid unnecessary onboarding copy inside cart and checkout.

## 21.2 Price transparency

The user must understand what contributes to the displayed subtotal.

Do not invent additional financial charges.

Use Indonesian Rupiah formatting consistently.

## 21.3 Action hierarchy

Examples:

\*\*Cart\*\*
- Primary: Checkout.
- Secondary: Continue Shopping.
- Item-level: Edit Quantity, Remove.

\*\*Remove Confirmation\*\*
- Primary destructive action: Hapus Buku.
- Secondary: Batal.

\*\*Order Summary\*\*
- Primary: Konfirmasi Pesanan.
- Secondary: Kembali ke Keranjang.

Avoid making every action visually primary.

## 21.4 Confirmation semantics

Differentiate:

- \*\*Buku ditambahkan ke keranjang.\*\*
- \*\*Pesanan dibuat.\*\*
- \*\*Menunggu pembayaran.\*\*
- \*\*Pembayaran berhasil.\*\*

The final state belongs to F06, not F05.

Do not treat these as interchangeable.

## 21.5 Empty-state quality

An empty cart does not need a large illustration or inspirational description.

It needs a clear explanation and a path back to the catalog.
