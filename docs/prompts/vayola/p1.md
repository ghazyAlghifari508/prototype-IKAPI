# 5. BACKEND CATALOG ARCHITECTURE

Gunakan Laravel + Eloquent.

Implementasikan endpoint halaman katalog melalui arsitektur Inertia existing.

Jangan membuat Express API atau REST backend kedua.

Contoh rute konseptual:

```
GET /                 Beranda
GET /books            Katalog Buku
```

Nama route final harus mengikuti naming dan pola aktual repository.

Gunakan route names yang jelas dan Wayfinder bila sesuai.

Jangan membuat URL `/prototype` untuk website produksi.

## Backend query

Query katalog harus:

1. Membatasi buku pada status publik yang valid.
2. Mengambil metadata yang diperlukan.
3. Mengambil relasi penulis/penerbit/kategori secara efisien.
4. Menghindari N+1 queries.
5. Menggunakan urutan default yang stabil dan masuk akal.
6. Memiliki pagination untuk data besar.
7. Menghindari memuat seluruh database ke memori.
8. Tidak mengirim path PDF asli.
9. Tidak mengirim atribut internal yang tidak diperlukan ke browser.

Jika repository memiliki existing public Book Query/Service, gunakan kembali.

Jangan membuat abstraksi repository/service berlapis-lapis untuk query sederhana tanpa alasan nyata.

## Pagination

Gunakan mekanisme pagination resmi Laravel yang cocok dengan data dan UX.

Pertimbangkan `paginate`, `simplePaginate`, atau `cursorPaginate` berdasarkan kebutuhan nyata.

Untuk katalog awal, numbered pagination merupakan pilihan yang valid jika total dan navigasi halaman dibutuhkan.

Jangan membuat infinite scroll hanya karena dianggap modern.

Gunakan stable ordering agar tidak muncul duplicate/missing records secara tidak perlu.

Jumlah item per halaman harus dikonfigurasi secara konsisten dan dapat diubah, bukan tersebar dalam hardcode di banyak komponen.
