# 3. SOURCE OF TRUTH

## UC-06 — Melihat Detail Buku

Skenario menyebut:

1. User menekan kartu/gambar buku.
2. Backend mengambil informasi rinci dari database.
3. Sistem menampilkan sinopsis, harga, spesifikasi e-book, rating, dan penerbit.

Alternative:

Jika data tidak dapat diakses atau buku telah dihapus:

**"Gagal memuat detail buku."**

Pengguna diarahkan atau diberi jalur kembali ke katalog.

Skenario menyebut:

1. User berada di halaman detail.
2. User menekan `Preview Buku`.
3. Sistem memuat **berkas sampel** dari server.
4. Sistem menampilkan jendela atau halaman untuk membaca sampel.

Alternative:

Jika berkas sampel tidak tersedia:

**"Preview untuk buku ini belum tersedia."**

**Penting:** dokumen menyebut sampel buku, bukan akses penuh ke PDF asli.

# 5. BOOK DETAIL DATA CONTRACT

Gunakan canonical Book model.

Informasi relevan:

- Book ID.
- Judul.
- Penulis.
- Penerbit.
- Kategori.
- Cover.
- Sinopsis.
- Format e-book.
- Jumlah halaman.
- Harga awal.
- Harga aktif.
- Persentase diskon bila benar-benar berlaku.
- Rating/evaluasi jika tersedia dan valid.
- Preview availability.

Jangan membuat seluruh field baru jika existing model sudah tersedia.

## Avoid unsupported metadata

Jangan menambahkan:

- ISBN palsu.
- Tahun terbit palsu.
- Ukuran file palsu.
- Bahasa buku palsu.
- Rating 4.8 hardcoded.
- Total pembeli palsu.
- Jumlah stok e-book.
- Total download palsu.
- Bestseller badge tanpa data.

Jika sebuah field tidak tersedia, jangan mengarang nilainya.

Jika field wajib menurut spesifikasi tetapi belum disediakan model Dimas, dokumentasikan kontrak yang dibutuhkan dan lakukan perubahan skema hanya melalui koordinasi scope yang jelas.

# 6. PUBLICATION &amp; OWNERSHIP RULES

Detail buku harus menggunakan public visibility contract dari Prompt 01.

Jika buku:

- Draft.
- Unpublished.
- Rejected/taken down menurut aturan yang berlaku.
- Tidak tersedia bagi publik.

maka detail publik tidak boleh membocorkan isi metadata internal atau lokasi PDF asli.

Gunakan response yang sesuai, misalnya 404/not available berdasarkan policy existing.

Jangan mengekspos:

- Original PDF storage key.
- Internal private path.
- Admin moderation notes.
- Sensitive publisher bank data.
- Upload processing credentials.

Penerbit boleh mempunyai akses ke metadata bukunya pada modul miliknya sendiri, tetapi itu bukan alasan untuk membuka detail publik bagi semua pengguna.

# 11. PREVIEW BOOK — CORE SECURITY BOUNDARY

Ini bagian paling sensitif.

IKAPI menggunakan private original PDF.

**Preview harus menggunakan konten sampel yang diizinkan, bukan original PDF penuh.**

Dilarang:

- `<iframe>` ke original PDF yang bisa diakses publik.
- Public link ke original PDF.
- Mengirim original PDF ke browser untuk disembunyikan sebagian dengan CSS.
- Menggunakan JavaScript untuk membatasi halaman tetapi tetap mengunduh seluruh original PDF.
- Menggunakan URL permanen original PDF sebagai preview.
- Membuat tombol Download Original PDF.
- Menganggap semua buku otomatis boleh dipreview sepenuhnya.

Jangan menampilkan PDF asli penuh hanya karena user belum login.

## Expected preview architecture

```
Book Detail
     |
     v
Click Preview Buku
     |
     v
Check Preview Availability
     |
     +-- No sample
     |      |
     |      v
     |   Preview Unavailable
     |
     +-- Sample available
            |
            v
    Serve Allowed Sample
            |
            v
     Sample Reader UI
```

## Source of sample

Periksa apakah proyek memiliki:

- Approved sample PDF.
- Pre-rendered sample pages.
- Private preview derivatives.
- Existing backend preview rendering.
- Publisher-approved preview configuration.

Gunakan sumber yang sah.

**Jangan secara otomatis menentukan bahwa semua penerbit mengizinkan 10%, 5 halaman, atau 20 halaman untuk preview.**

Jumlah halaman dan kebijakan preview belum dinyatakan eksplisit dalam UC-08.

Jika jumlah sampel telah disetujui tim, ikuti kebijakan tersebut.

Jika belum:

- Catat kebutuhan keputusan.
- Jangan menciptakan angka sebagai aturan resmi.
- Jangan mengeluarkan seluruh PDF.
- Implementasikan flow preview untuk sampel yang memang tersedia.
- Tandai integrasi sample-generation yang belum ada sebagai blocker.

## Dimas dependency

UC-32 Dimas mengunggah original PDF, tetapi tidak otomatis berarti sample PDF sudah tersedia.

Jangan mengubah upload PDF Dimas tanpa memeriksa kontrak dan ownership.

Jika proses pembuatan sampel perlu ditambahkan ke pipeline, siapkan spesifikasi integrasi yang jelas:

- Source private original PDF.
- Approved page range.
- Secure server-side processing.
- Safe output storage.
- Sample availability state.
- Cleanup ketika buku berubah/unpublish.

Jangan secara diam-diam membuat seluruh ingestion pipeline di Prompt Vayola.

# 12. PREVIEW DELIVERY &amp; SECURITY

Gunakan backend untuk mengendalikan akses ke sample.

Jika sample memang diperbolehkan ditampilkan publik, tetap pastikan server hanya menyajikan sample asset yang disetujui.

Jika sample disimpan privat, gunakan mekanisme authorized delivery yang sesuai.

Baca Laravel Filesystem documentation untuk storage driver yang benar.

Perhatikan:

- Local private disk.
- R2/S3-compatible storage.
- Temporary URLs jika sesuai kebutuhan.
- Signed routes bila digunakan.
- File identifier yang aman.
- Tidak mengekspos original PDF.
- Path traversal protection.
- Correct content type.
- Cache behavior yang sesuai dengan visibilitas konten.
- Tidak ada credential storage yang dikirim ke React.

Jangan menggunakan signed URL original PDF yang memberikan akses penuh hanya untuk membuat preview.

## Preview lifecycle

Jika penerbit:

- Mengganti original PDF.
- Menonaktifkan buku.
- Mengubah preview policy.

sample preview tidak boleh diam-diam menjadi stale atau melanggar aturan baru.

Gunakan kontrak invalidation/availability yang benar-benar tersedia.

Jangan menciptakan pipeline pemrosesan berlebihan jika belum diperlukan, tetapi dokumentasikan dependency dengan jelas.
