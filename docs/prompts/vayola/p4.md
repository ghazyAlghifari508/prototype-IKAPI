# 4. HISTORY SCOPE — SESSION-FIRST

UC-27 menyebut histori **sesi penjelajahan**.

Artinya, jangan langsung menafsirkan fitur ini sebagai histori permanen seluruh aktivitas pengguna yang disimpan lintas perangkat selamanya.

Gunakan model sesuai kebutuhan:

**Session-oriented recently viewed history.**

## Recommended approach

- Simpan daftar book identifiers dalam Laravel session atau cache yang terkait dengan sesi.
- Pertahankan urutan.
- Hindari duplikasi.
- Batasi jumlah item.
- Gunakan lifecycle/expiration yang masuk akal.
- Jangan menyimpan seluruh metadata buku berulang kali dalam session.
- Jangan membuat persistent tracking lintas perangkat tanpa kebutuhan resmi.

Jika existing architecture sudah memiliki tabel recently viewed yang sesuai UC-27, reuse dan evaluasi lifecycle-nya.

Jangan memindahkan data dari database ke localStorage hanya karena lebih mudah.

## Authentication behavior

Katalog dan detail buku mungkin dapat dikunjungi guest.

Jika public browsing diperbolehkan:

- Riwayat sesi guest dapat berfungsi.
- Jangan mewajibkan login hanya untuk melihat recently viewed.
- Jangan menggabungkan histori sesi guest dengan akun berbeda secara sembarangan.
- Pastikan sesi antar-pengunjung tidak tercampur.

Jika proyek memiliki kebijakan lain, ikuti kebijakan yang sudah disepakati.

Jangan menganggap seluruh riwayat harus tersimpan permanen pada User model.

# 6. DEDUPLICATION &amp; ORDERING

Ketika buku yang sama dibuka lagi, pindahkan ke urutan paling baru.

Contoh:


Gunakan canonical Book ID sebagai identifier.

Jangan menggunakan judul buku sebagai unique identifier karena beberapa buku dapat mempunyai judul sama.

## Storage limit

Gunakan jumlah maksimum yang terbatas dan konsisten.

Jumlah pastinya dapat ditetapkan sebagai konfigurasi implementasi yang wajar berdasarkan UX dan ukuran payload. Jangan mengklaim angka pilihan developer sebagai aturan resmi UC-27.

Jangan membuat sistem infinite history storage.

# 7. HISTORY STORAGE &amp; CACHE

Periksa session/cache driver existing.

Jika menggunakan Laravel session:

- Gunakan session API yang benar.
- Pertahankan konsistensi write/read.
- Jangan membuat cookie dengan seluruh data buku.
- Jangan mengirim informasi sensitif ke browser.

Jika menggunakan Laravel Cache:

- Gunakan key yang terisolasi per sesi/pengguna sesuai kontrak.
- Gunakan TTL yang tepat.
- Hindari key collisions.
- Jangan membuat global cache key seperti `recent_books` untuk seluruh pengguna.

Jangan menggunakan Redis hanya karena fitur recently viewed ada. Database/session cache existing sudah dapat mencukupi jika sesuai.

## Privacy boundary

- User A tidak boleh melihat history B.
- Session guest tidak boleh melihat history guest lain.
- Session lama harus mengikuti lifecycle yang disepakati.
- Tidak boleh ada data buku privat yang bocor.
- Jangan menyimpan IP address atau fingerprint pengguna hanya untuk recently viewed.
- Jangan mengirim history ke provider eksternal.
- Jangan mencatat aktivitas pengguna secara permanen tanpa kebutuhan bisnis yang jelas.

# 8. LOAD FRESH BOOK DATA

History sebaiknya menyimpan Book ID, bukan menyalin seluruh objek Book.

Saat menampilkan section:

1. Baca daftar ID dari session/cache.
2. Ambil data buku yang masih eligible.
3. Ambil cover, title, author, dan price terbaru.
4. Pertahankan urutan most recently viewed.
5. Hapus atau abaikan ID yang tidak valid.
6. Render cards menggunakan komponen existing.

## Why fresh data matters

Contoh:

- Kemarin buku seharga Rp50.000.
- Sekarang penerbit mengubah harga menjadi Rp45.000.
- Recently Viewed harus menampilkan harga katalog yang berlaku sekarang.

History adalah daftar kunjungan, bukan snapshot transaksi.

Jangan menggunakan harga lama dari cache history sebagai harga penjualan.

## Visibility

Jika buku telah:

- Dihapus.
- Unpublished.
- Dibatasi berdasarkan moderation/availability.

maka buku tidak boleh terus tampil sebagai kartu publik.

Jangan membiarkan Recently Viewed membuka akses buku yang tidak tersedia hanya karena ID-nya masih tercatat.

Gunakan public book scope yang sama dengan katalog.
