## Required behavior

- Search hanya terhadap buku milik pengguna.
- Jangan mencari seluruh Book lalu menyaring User ID di frontend.
- User A tidak bisa melihat buku User B dengan mengganti query.
- Payment pending tidak otomatis membuat hasil buku.
- Favorite yang belum dibeli tidak otomatis masuk koleksi milik pengguna.
- Search tidak memberikan entitlement baru.
- Search tidak memanggil Midtrans.
- Search tidak membuka original PDF.

## Important: Favorites tab

Devina UC-23 mempunyai tab Favorit yang bisa saja berisi buku yang belum dimiliki.

Karena itu, pisahkan:

**Search pada tab koleksi:**  
Cari judul dalam buku yang dimiliki.

**Search pada tab Favorit:**  
Jika UI Devina menampilkan favorit yang belum dibeli, cari hanya dalam daftar favorit user dan tetap pertahankan perbedaan entitlement.

Jangan menganggap semua hasil Favorit otomatis memiliki tombol Baca.

Jangan mengubah definisi favorit agar search terlihat seragam.

# 5. SEARCH QUERY BEHAVIOR

Gunakan satu query state yang jelas.

Contoh:

```
/library
/library?q=laravel
/library?tab=reading&q=laravel
/library?tab=favorites&q=database
```

URL hanyalah contoh.

Gunakan naming dan route existing.

## Functional rules

- Keyword ditrim dengan benar.
- Case-insensitive search bila sesuai PostgreSQL strategy.
- Input kosong = kembali ke list normal.
- Input whitespace-only = tidak membuat query yang tidak berguna.
- Search bekerja pada seluruh koleksi, bukan hanya page pertama.
- Mengganti keyword mereset pagination.
- Menghapus keyword mempertahankan tab aktif.
- Mengganti tab dapat mempertahankan keyword jika UX existing memang cocok.
- Refresh tidak membuat hasil berbeda secara tidak wajar.
- Browser Back/Forward bekerja.

## Server-side vs client-side

Jika perpustakaan masih kecil dan seluruh data sudah dimuat secara sah, client filtering mungkin tampak cukup.

Namun untuk implementasi website yang dapat berkembang, utamakan filter pada query backend/paginated source agar pencarian tidak hanya berlaku pada item yang kebetulan sedang dirender.

Jangan memuat semua buku user secara paksa hanya demi memfilter di browser.

Jika menggunakan search-as-you-type, debounce request agar tidak mengirim query pada setiap render atau keystroke secara berlebihan.

Jangan menambahkan provider full-text search eksternal untuk fitur ini.

# 8. EMPTY STATE HANDLING

Bedakan:

## A. User belum memiliki koleksi

Gunakan empty state Devina:

**"Perpustakaan Anda masih kosong."**

Sertakan CTA katalog sesuai UC-23.

## B. User memiliki buku, tetapi keyword tidak cocok

Gunakan UC-24:

**"Buku tidak ditemukan di perpustakaan Anda."**

Sediakan tindakan sederhana:

- Hapus pencarian.
- Tampilkan semua buku.

## C. Tab tertentu kosong

Gunakan empty state sesuai tab.

Jangan menampilkan "Perpustakaan Anda masih kosong" ketika sebenarnya hanya tab Sedang Dibaca tidak memiliki hasil.
