# 4. CANONICAL BOOK QUERY

Gunakan model Dimas.

```
Authenticated Publisher
        |
        v
Authorized Publisher Identity
        |
        v
Books WHERE publisher = current publisher
        |
        +-- Cover
        +-- Title
        +-- Price
        +-- Discount
        +-- Publication Status
        +-- Paid Sales Count
```

Semua filtering publisher dilakukan backend.

## Required distinctions

Katalog Vayola hanya menampilkan buku publik yang eligible.

Daftar Kelola Buku Aprila menampilkan **semua buku milik penerbit itu sendiri**, termasuk draft/unpublished, sesuai hak akses.

Jangan menggunakan query katalog publik secara langsung jika akibatnya buku draft tidak terlihat oleh penerbit.

Sebaliknya, jangan menggunakan query Kelola Buku untuk menampilkan draft di katalog pembeli.

Gunakan scoped queries yang berbeda tujuannya tetapi tetap membaca Book model yang sama.

# 7. SALES COUNT — IMPORTANT INTEGRATION

Kolom **Jumlah Terjual** tidak boleh diisi angka acak.

Hitung berdasarkan verified paid order items dari Ghazy.

Contoh:

```
Order A: Buku X quantity 2, paid
Order B: Buku X quantity 3, paid
Order C: Buku X quantity 1, pending

Buku X Terjual = 5
```

Jangan menghitung pending order.

Jangan menghitung semua order tanpa status.

Jangan menghitung harga/quantity buku penerbit lain.

Perhatikan:

- Quantity item.
- Verified payment status.
- Refund/reversal policy jika ada.
- Duplicate payment notifications.
- Soft-deleted historical items.

Jangan membuat counter baru yang bertambah setiap kali halaman dibuka.

Jika canonical sales metrics sudah tersedia di dashboard Dimas, reuse aturan query yang sama.

Jika order/payment belum tersedia, jangan mengisi Terjual dengan angka fiktif.

Tampilkan keadaan tidak tersedia yang akurat dan dokumentasikan dependency jika perlu.

# 9. PUBLICATION STATUS CONTROL

UC-33 meminta toggle Publish/Unpublish.

Gunakan endpoint/action Dimas.

## Expected behavior

1. Pengguna mengubah status.
2. Frontend mengirim request ke backend.
3. Backend memverifikasi ownership dan transisi.
4. Backend menyimpan state.
5. UI mengikuti hasil response.
6. Jika gagal, toggle kembali ke status sebelumnya.
7. Feedback tampil sekali.

Jangan mengubah status di React saja.

## Moderation consideration

Skenario UC-32 menyebut Publish dapat tampil langsung, tetapi arsitektur juga membahas moderasi katalog.

Jika moderation state tersedia:

- Jangan mengabaikannya.
- Jangan membuat toggle bypass review admin.
- Bedakan niat publish dari status publikasi final jika kontrak mengharuskan.

Jika aturan belum disepakati:

- Catat konflik.
- Jangan mengarang workflow moderator sendiri.
- Jangan klaim toggle dapat menerbitkan buku tanpa pemeriksaan policy.

## Toggle UX

Status harus jelas secara teks.

Jangan mengandalkan warna saja.

Contoh:

- Terbit.
- Draft.

Gunakan istilah yang sama dengan model/UX existing.

Jangan membuat confirm modal untuk setiap perubahan jika tidak diperlukan, tetapi tindakan yang berisiko memengaruhi ketersediaan katalog harus memiliki feedback yang tepat.
