# 6. PROOF AVAILABILITY RULES

Tombol bukti harus merepresentasikan kondisi nyata.

## Case A — Masih Dalam Proses

Tidak ada bukti transfer final.

Tampilkan state yang jelas.

Jika user mencoba membuka:

**"Pencairan masih diproses, bukti transfer belum tersedia."**

Ikuti status workflow yang disepakati Lydia.

Tidak boleh mengklaim ada bukti transfer sukses apabila transaksi tidak menghasilkan transfer yang selesai.

# 7. SECURE FILE STORAGE

Bukti transfer bank adalah berkas sensitif.

**Jangan memberikan public permanent URL yang dapat diakses siapa saja.**

Gunakan Laravel private storage.

Jika backend menggunakan R2/S3-compatible disk:

- Pertahankan visibility private.
- Gunakan authorized endpoint atau mekanisme akses sementara yang memenuhi kontrol authorization.
- Jangan mengirim storage credentials ke browser.
- Jangan mengungkap internal file path.
- Jangan mengandalkan obscurity dari nama file.

## Conceptual file flow

```
Publisher Clicks Lihat Bukti
            |
            v
Authenticated Laravel Route
            |
            v
Authorize Payout Ownership
            |
            v
Check Completed Status
            |
            v
Check Proof Exists
            |
            v
Private Storage Read
            |
            v
Secure Preview Response
```

File response harus mempunyai:

- Content type yang benar.
- Safe filename.
- Header/cache policy yang sesuai dokumen sensitif.
- Tidak mengungkap data internal.
- Penanganan missing file.
- Penanganan unauthorized request.

Jangan membiarkan user mengirim arbitrary filesystem path.

Jangan menggunakan `Storage::url()` pada private proof lalu menaruh link publik secara sembarangan.

# 10. BACKEND AUTHORIZATION

Ini bagian wajib.

Setiap request untuk melihat proof harus memeriksa:

1. User login.
2. User adalah penerbit yang benar.
3. Account status mengizinkan akses sesuai policy.
4. Payout request ada.
5. Payout request milik publisher tersebut.
6. Payout status memenuhi syarat.
7. Bukti benar-benar terkait payout tersebut.
8. File tersedia.
9. File berasal dari private disk yang diizinkan.

Jangan menerima publisher ID dari frontend sebagai sumber otoritas.

## IDOR prevention

Contoh:

```
Publisher A
   |
   v
GET /publisher/payouts/123/proof
```

Jika payout 123 milik Publisher B:

**DENY.**

Jangan tetap mengirim file lalu berharap UI tidak menampilkannya.

Gunakan Policies/Gates dan server-side ownership.

Jika status tidak eligible, gunakan response yang konsisten dengan kebijakan informasi.

# 11. PRIVACY, CACHE &amp; DOWNLOAD POLICY

Bukti transfer tidak boleh:

- Terekspos melalui `/storage/public/...`.
- Diindeks mesin pencari.
- Dapat dibuka menggunakan permanent unauthenticated URL.
- Ter-cache secara publik pada CDN.
- Muncul dalam log sebagai full file contents.
- Dibagikan ke penerbit lain.
- Disimpan sebagai base64 besar dalam global Inertia props tanpa kebutuhan.

Gunakan response headers yang sesuai sensitivitas.

Perhatikan bahwa meskipun preview aman, penerbit yang berwenang masih dapat menyimpan atau mengambil tangkapan layar dokumen yang memang boleh mereka lihat.

Jangan menjanjikan perlindungan yang mustahil.

Jika opsi Unduh Bukti tidak diminta UC-37, tidak perlu membuat fitur download tersendiri. Fokus pada modal preview.
