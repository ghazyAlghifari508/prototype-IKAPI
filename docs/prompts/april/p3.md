# 6. AGENDA CALENDAR

UC-25 secara eksplisit mengharuskan **kalender event**.

Jangan mengganti kalender dengan empat kartu event lalu mengklaim requirement terpenuhi.

Implementasikan tampilan kalender yang benar-benar merepresentasikan tanggal acara dari database.

## Expected behavior

- Bulan/tahun aktif jelas.
- Navigasi bulan sebelumnya/berikutnya.
- Tanggal acara ditandai secara proporsional.
- Pengguna dapat memilih tanggal.
- Agenda pada tanggal tersebut dapat dibuka.
- Jika satu tanggal memiliki beberapa acara, semua dapat diakses.
- Event yang berlangsung beberapa hari ditangani sesuai kontrak.
- Tidak menampilkan event di tanggal yang salah akibat timezone.
- Kalender responsive.
- Navigasi keyboard jika komponen mendukungnya.
- View agenda berbasis list tetap dapat digunakan pada mobile bila kalender grid terlalu sempit.

## Date/time consistency

Periksa:

- Timezone acara.
- Date-only vs timestamp.
- Start/end time.
- Multiple-day events.
- Urutan acara.
- Event dengan waktu belum ditetapkan.

Jangan menganggap seluruh event dimulai pukul 09.00.

Jangan menampilkan lokasi/Google Maps link yang tidak tersedia.

## Calendar component

Gunakan komponen existing yang maintained.

Jika calendar library belum tersedia:

- Evaluasi komponen ready-made yang kompatibel dengan React 19.
- Gunakan hanya dependency yang diperlukan.
- Jangan membuat seluruh date-calendar framework dari nol tanpa alasan.
- Jangan menambahkan full scheduling/event booking system.

Tidak perlu membuat fitur:

- Pemesanan tiket.
- Registrasi event.
- Pembayaran tiket.
- Reminder event.
- Kalender Google synchronization.

Fitur tersebut tidak diminta UC-25.

# 8. BERITA LITERASI

Tampilkan daftar ringkasan berita dari database.

Urutan:

- Artikel terbaru terlebih dahulu menurut `published_at` yang sah.

Metadata:

- Judul.
- Tanggal publikasi.
- Ringkasan.
- Cover bila ada.
- Author jika tersedia.

Jangan membuat headline dari AI berdasarkan foto random.

## Article detail

Halaman detail harus:

- Menampilkan judul utuh.
- Menampilkan tanggal publikasi.
- Menampilkan isi artikel lengkap.
- Mendukung paragraf, heading, gambar, dan list sesuai model konten.
- Memiliki readable line length.
- Mendukung mobile.
- Mempunyai jalur kembali ke daftar berita.

## Rich text security

Konten dari database bisa berupa HTML/rich text.

Jangan merender HTML mentah tanpa memahami asal dan proses sanitization.

Gunakan sanitization yang sesuai dan pastikan konten admin/editor terkontrol.

Jangan percaya isi artikel hanya karena tersimpan di database.

Cegah:

- XSS.
- Unsafe embeds.
- `javascript:` links.
- Arbitrary script tags.
- Injection melalui preview text.

Jangan membuat iframe arbitrary untuk setiap artikel.

# 12. EMPTY &amp; ERROR STATES

**"Belum ada agenda kegiatan saat ini."**

**"Belum ada berita literasi yang diterbitkan."**

- Tetap tampilkan agenda.

- Jangan menyamarkan database error menjadi konten kosong.
- Tampilkan fallback yang sesuai.

Jika detail event/article tidak ditemukan:

- Gunakan 404/not available yang aman.
- Sediakan link kembali.
- Jangan expose internal record.
