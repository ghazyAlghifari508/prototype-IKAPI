# 4. MULTI-PUBLISHER SALES ISOLATION

Ini aturan terpenting.

Contoh:

```
Order #1001 — PAID

Buyer A
   |
   +-- Buku X
   |     Publisher A
   |     Rp 40.000
   |
   +-- Buku Y
         Publisher B
         Rp 60.000
```

Hasil untuk Publisher A:

```
Order #1001
Buku X
Quantity 1
Bagian penjualan Buku X
```

Hasil untuk Publisher B:

```
Order #1001
Buku Y
Quantity 1
Bagian penjualan Buku Y
```

Jangan menampilkan total Rp100.000 sebagai pendapatan masing-masing penerbit.

Jangan menampilkan rincian buku penerbit lain jika tidak relevan.

## Backend scoping

- Authenticated publisher dari session.
- Relasi OrderItem → Book/Publisher atau snapshot publisher.
- Canonical verified paid status.
- No client-controlled publisher ID.
- No cross-publisher order leakage.
- No global order list in Inertia props.
- No sensitive buyer/payment data yang tidak diperlukan.

Gunakan query yang scoped di backend.

Jangan mengirim semua order lalu memfilter di React.

# 6. ORDER/ITEM ROW DESIGN

UC-34 meminta Nomor Pesanan sekaligus Judul Buku dan Jumlah.

Satu order bisa mempunyai beberapa buku penerbit yang sama.

Jangan membuat jumlah order berlipat atau salah menghitung pendapatan.

Pilih representasi sesuai struktur data:

### Option A — One row per sale item

```
ORDER        BUKU      QTY    PENDAPATAN    STATUS
ORD-001      Buku A     1     Rp ...         Lunas
ORD-001      Buku B     2     Rp ...         Lunas
```

### Option B — Group by order

```
ORD-001 | 11 Nov 2026 | 3 buku | Lunas

    Buku A  Qty 1
    Buku B  Qty 2

    Pendapatan Bersih: Rp ...
```

Pilih strategi yang paling jelas dan cocok dengan query/UX existing.

Jangan memakai satu row per order jika akibatnya judul salah satu buku hilang.

Jangan memakai satu row per item tanpa menyadari nomor order dapat muncul berulang secara sah.

Pastikan pagination dan count semantics sesuai representasi.

- Tampilkan informasi yang dapat dibuktikan seperti gross item sale bila sesuai UX yang disetujui.
- Jangan memberi label "Pendapatan Bersih" pada gross.
- Tandai net earnings sebagai unavailable/blocked.
- Dokumentasikan kebutuhan finalisasi aturan.
- Jangan mengklaim kolom finansial sepenuhnya selesai.

## Money arithmetic

Gunakan integer/exact numeric backend.

Jangan menghitung uang dengan floating point React.
