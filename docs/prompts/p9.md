Perbaiki prototype:

Gunakan file terbaru yang benar-benar ada di direktori proyek. Jika terdapat beberapa versi atau nama file dengan suffix berbeda, identifikasi file aktif terlebih dahulu.

- Pertahankan halaman keranjang sebagai halaman utama belanja.
- Pertahankan langkah konfirmasi pesanan, tetapi sederhanakan UI-nya.

- Jangan mengarang transaksi berhasil.
- Jangan membuat tiruan Midtrans Snap dan mengklaimnya sebagai gateway pembayaran resmi.
- Samakan navbar dan footer dengan desain terbaru beranda IKAPI.

\*\*Scope pekerjaan adalah prototype HTML dan integrasi navigasi yang relevan. Jangan melakukan migrasi framework ataupun membangun backend pembayaran baru tanpa kebutuhan.\*\*

# 2. Audit Wajib Sebelum Implementasi

Baca seluruh file HTML, CSS, dan JavaScript.

Jangan langsung mengganti warna atau membuat UI baru.

Temuan awal dari file yang perlu diperiksa:

### A. Modal konfirmasi muncul secara default

Periksa elemen \`modal-order-confirm\`.

Pada prototype yang diberikan, modal menggunakan class \`opacity-100\` dan tidak berada dalam state tersembunyi saat dokumen pertama dimuat.

Pastikan modal hanya muncul setelah pengguna menekan tombol checkout.

### B. Simulasi pembayaran bercampur dengan checkout

Saat ini terdapat:

\`SIMULASI STATUS RESPONS MIDTRANS\`

Beserta tombol:
- Sukses Bayar.
- Menunggu.
- Gagal.
- Kedaluwarsa.

Hapus kontrol ini dari antarmuka pelanggan.

### C. Status transaksi dimanipulasi JavaScript

Periksa:
- \`simulatePaymentFlow()\`
- \`renderStatusView()\`
- \`checkPaymentStatus()\`
- \`triggerMidtransPayment()\`

Fungsi \`checkPaymentStatus()\` pada prototype saat ini otomatis mengubah tampilan menjadi berhasil melalui timer.

Itu bukan pengecekan pembayaran yang sebenarnya.

### D. Invoice hanya disimulasikan

Periksa:

\`downloadInvoiceMock()\`

Fungsi tersebut hanya memunculkan toast, bukan mengunduh atau menampilkan invoice sebenarnya.

Jangan mempertahankan perilaku menyesatkan.

### E. Total keranjang belum konsisten secara dinamis

Periksa fungsi:

\`removeCartItem()\`

Saat buku dihapus, indikator jumlah keranjang berubah, tetapi subtotal dan total pembayaran masih tertulis secara statis dalam HTML.

Perbaiki agar seluruh informasi keranjang berasal dari data yang sama.

### F. Modal dan status pembayaran tercampur dalam satu dokumen

Pisahkan elemen yang memang merupakan halaman sendiri.

Jangan sekadar menyembunyikan empat status menggunakan CSS sementara seluruh markup tetap berada di dalam popup keranjang.

# 5. Global Design Rules

## Identitas Visual

Gunakan desain IKAPI Store terbaru sebagai sumber acuan.

Pertahankan identitas:
- Logo IKAPI Jawa Barat.
- Plus Jakarta Sans atau font final yang dipakai beranda.
- Warna interaksi utama IKAPI.
- Typography konsisten.
- Spacing terukur.
- Komponen e-commerce yang jelas.

### Masalah typography saat ini

Pada screenshot, banyak teks terlihat menggunakan font serif seperti Times New Roman.

Ini tidak konsisten dengan beranda, katalog, dan detail buku versi terbaru.

Periksa penyebab aktual:
- Font tidak termuat.
- Utility class tidak terpasang.
- Tailwind CDN atau konfigurasi class tidak bekerja.
- Styling tertimpa.
- Fallback font.

Jangan langsung menyimpulkan salah satu penyebab tanpa inspeksi.

\*\*Seluruh halaman checkout dan pembayaran harus menggunakan typography yang konsisten dengan sistem desain IKAPI.\*\*

## Larangan AI Slop

Jangan menggunakan:
- Random dots.
- Glowing circles.
- Gradient blobs.
- Shadow besar.
- Badge warna-warni sebagai dekorasi.
- Emoji untuk status.
- Ikon besar dalam lingkaran pastel bertingkat.
- Copy marketing teknis.
- Testimonial pembayaran.
- Klaim keamanan tanpa sumber.
- Card kecil di dalam card besar tanpa alasan.
- Warna berbeda pada tiap baris.
- Animasi pembayaran palsu.
- Mockup buku 3D berbasis CSS.
- Decorative dividers.
- Eyebrow uppercase pada setiap heading.
- Tombol yang berfungsi sebagai demo tetapi terlihat seperti fitur pelanggan.

\*\*Catatan:\*\* warna status tetap boleh dipakai secara fungsional, misalnya untuk membedakan berhasil dan gagal. Yang dilarang adalah membuat seluruh UI menjadi kumpulan badge dan background warna-warni yang tidak diperlukan.

## Prinsip visual

Halaman harus terlihat menarik melalui:
- Gambar sampul berkualitas.
- Layout yang terarah.
- Hierarki teks.
- Keseimbangan kolom.
- Ukuran gambar.
- Spacing.
- Interaksi yang jelas.

Jangan menyamakan anti-AI-slop dengan membuat halaman polos.

# 10. Perbaikan Alur Midtrans Snap

## Masalah utama

Prototype saat ini membuat modal yang menyerupai Midtrans Snap dengan label:

"MIDTRANS SNAP"

"Portal Pembayaran Resmi"

Di dalamnya terdapat pilihan metode pembayaran dan tombol untuk menentukan status transaksi.

Ini tidak boleh menjadi desain checkout pelanggan yang diklaim sebagai Midtrans sebenarnya.

## Keputusan implementasi

### Jika integrasi Midtrans benar-benar tersedia

Gunakan Snap resmi dengan:
- Token transaksi dari backend.
- Library Snap.js resmi.
- Metode pembayaran yang diaktifkan untuk merchant.
- Callback sesuai dokumentasi.
- Verifikasi status melalui backend.

Jangan membangun ulang UI pemilihan metode pembayaran Midtrans menggunakan HTML buatan sendiri apabila implementasi memang menggunakan Snap.

### Jika masih berupa prototype HTML statis

Jangan menyamarkan modal tiruan sebagai transaksi nyata.

Pertahankan struktur checkout dan modal konfirmasi.

Setelah langkah konfirmasi, UI boleh menjelaskan bahwa pembayaran sebenarnya memerlukan integrasi gateway, tanpa menampilkan transaksi berhasil palsu.

Empat halaman status tetap dibuat sebagai prototype terpisah untuk peninjauan visual.

### Yang wajib dihapus dari checkout pelanggan

- Panel "SIMULASI STATUS RESPONS MIDTRANS".
- Tombol Sukses Bayar.
- Tombol Menunggu.
- Tombol Gagal.
- Tombol Kedaluwarsa.
- Fungsi yang mengubah status berhasil tanpa transaksi.
- Toast "Pembayaran berhasil divalidasi!" tanpa verifikasi.
- Simulasi invoice yang mengklaim file sedang diunduh.

### Informasi metode pembayaran

Jangan mengklaim:
- Seluruh e-wallet didukung.
- Pembayaran terverifikasi dalam 24 jam.
- Bank BJB mempunyai fitur tertentu.
- Semua channel tersedia.

Kecuali informasi tersebut sudah diverifikasi berdasarkan konfigurasi merchant dan dokumentasi Midtrans.

\*\*Jangan membuat UI resmi Midtrans versi buatan sendiri hanya untuk memenuhi screenshot prototype.\*\*

- Header.

## Jangan gunakan modal besar

Pada screenshot sekarang, setiap status ditampilkan sebagai modal besar dengan overlay gelap.

Untuk file HTML terpisah, ubah menjadi \*\*dedicated payment status page\*\*.

Artinya:
- Tidak ada background halaman yang diblur.
- Tidak ada overlay modal.
- Tidak ada tombol X ala popup.
