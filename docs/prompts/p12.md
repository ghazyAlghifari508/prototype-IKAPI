6. Jika gagal, tampilkan pesan yang jelas.
7. Jangan hilangkan input pengguna saat gagal.
8. Jangan mengirim ulang permintaan secara tidak sengaja.

### Jika masih HTML prototype statis

Implementasikan demo perubahan profil pada state lokal selama sesi halaman.

Contoh:

- Nama berubah di sidebar.
- Avatar berubah.
- Data form mengikuti perubahan.
- Tombol Batal mengembalikan perubahan yang belum dikonfirmasi.

Namun jangan menampilkan klaim bahwa data tersimpan di database.

### Copy feedback prototype

Jika demonstrasi state lokal memang diterapkan, gunakan pesan yang jujur, misalnya:

**Perubahan ditampilkan pada pratinjau.**

Jangan gunakan:

- Berhasil Disinkronkan.
- Profil Tersimpan di Database.
- Perubahan Tersimpan Permanen.
- Identitas Berhasil Diverifikasi.

Kecuali memang ada operasi nyata yang mendukung klaim tersebut.

### Validasi

Ikuti praktik WCAG:

- Label setiap field jelas.
- Field wajib ditandai sesuai kebutuhan.
- Error dijelaskan dalam teks.
- Error ditampilkan dekat field.
- Warna tidak menjadi satu-satunya indikator.
- Fokus dapat diarahkan ke field yang bermasalah.
- Feedback dapat dikenali oleh teknologi bantu.

Referensi:

[https://www.w3.org/TR/WCAG22/](https://www.w3.org/TR/WCAG22/)

# 16. Perbaikan Tombol Batal

## Masalah

Tombol saat ini memakai:

`type="reset"`

Reset native akan mengembalikan nilai form sesuai default HTML, bukan selalu berdasarkan state profil terakhir yang valid.

Ini bisa menyebabkan hasil tidak konsisten setelah interaksi demo.

## Keputusan

Tombol **Batal** harus mengembalikan perubahan yang belum disimpan atau dikonfirmasi.

Jika pengguna mengganti nama dan foto lalu menekan Batal:

- Nama kembali seperti state sebelumnya.
- Foto kembali seperti sebelumnya.
- Input kembali sesuai data awal state yang berlaku.
- Tidak muncul toast sukses.
- Tidak terjadi penyimpanan.

Jangan otomatis menavigasi pengguna keluar halaman ketika menekan Batal.

Jika ada perubahan yang belum disimpan dan pengguna berpindah menu, pertimbangkan konfirmasi hanya jika memang diperlukan.

Jangan menambahkan dialog konfirmasi untuk setiap perubahan kecil.
