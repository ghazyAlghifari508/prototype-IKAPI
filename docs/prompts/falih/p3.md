# 4. BOOKMARK VS READING PROGRESS

Ini harus dipisahkan dengan jelas.

```
READER BOOK A
    |
    +-- Reading Progress
    |      |
    |      +-- Last Page: 42
    |
    +-- Bookmarks
           |
           +-- Page 10
           +-- Page 28
           +-- Page 65
```

**Reading progress:**

- Satu posisi baca terakhir per user dan buku.
- Berubah otomatis saat membaca.
- Sudah dibuat pada Prompt 02.

**Bookmark:**

- Banyak penanda halaman per user dan buku.
- Dibuat melalui tindakan pengguna.
- Tidak berubah hanya karena pengguna berpindah halaman.

Jangan menggunakan update progress sebagai tindakan Add Bookmark.

Jangan membuat satu posisi baca menjadi banyak bookmark otomatis.

# 5. BOOKMARK DATA CONTRACT

Kontrak konseptual:

```
Bookmark
   |
   +-- User ID
   +-- Book ID
   +-- Page Number
   +-- Created At
```

Gunakan model existing jika ada.

## Database integrity

Pastikan:

- Bookmark milik authenticated user.
- Bookmark terkait buku yang valid.
- Nomor halaman valid.
- Tidak ada duplikasi untuk kombinasi user, buku, halaman.
- Constraint unik database tersedia bila sesuai model.
- Foreign key benar.
- Tidak ada bookmark yang terkait user lain karena manipulasi request.

Jangan menyimpan bookmark permanen hanya pada React state atau localStorage.

## Page validation

Gunakan page count dari reader backend.

Tolak:

- Halaman 0.
- Halaman negatif.
- Halaman melebihi total.
- Nomor halaman noninteger.
- Buku yang tidak dapat diakses.
- Book ID palsu.

Jangan menganggap client-supplied page count tepercaya.

```
     |          |

Bookmarked       |
                 v
          Confirm Success
```

Gunakan Laravel authorization yang sudah dibuat pada Prompt 02.

Jangan membuat authentication check versi bookmark yang berbeda.

## Duplicate protection

Periksa duplikasi server-side.

Jangan hanya memakai `disabled` button di React.

Database constraint harus mampu menangani repeated/concurrent requests jika schema mendukungnya.

Jika dua request membuat bookmark identik hampir bersamaan, hasilnya harus tetap satu bookmark.

Jangan menyembunyikan database exception mentah di UI.

# 8. NAVIGATION TO BOOKMARKS

Ketika pengguna memilih halaman dari daftar bookmark:

1. Periksa bookmark valid.
2. Pastikan halaman terkait buku yang sedang dibaca.
3. Verifikasi entitlement masih berlaku.
4. Navigasikan reader ke halaman.
5. Reading progress mengikuti perilaku Prompt 02.
6. Jangan mengganti daftar bookmark.

Jika halaman bookmark tidak lagi tersedia karena PDF diganti:

- Jangan crash.
- Tangani secara aman.
- Gunakan kebijakan rekonsiliasi halaman yang disepakati.
- Jangan membuka halaman PDF di luar rentang valid.

Jangan membuat endpoint yang menerima arbitrary storage path.
