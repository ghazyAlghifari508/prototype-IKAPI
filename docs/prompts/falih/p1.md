# 4. CANONICAL CART DATA MODEL

Rancang satu sumber data keranjang.

```
Authenticated Buyer
         |
         v
       Cart
         |
         +-- CartItem
         |      |
         |      +-- Book ID
         |      +-- Quantity
         |
         +-- CartItem ...
```

Gunakan model dan relasi yang sesuai dengan codebase.

Jangan membuat:

- `carts` dan `shopping_carts` dengan makna sama.
- Cart data permanen pada session dan tabel database tanpa strategi sinkronisasi.
- Duplikasi buku karena tombol diklik berulang.
- Harga final transaksi yang dipercaya dari frontend.

## Data integrity

Pastikan:

- Keranjang terhubung ke User.
- Item mengacu pada Book yang valid.
- Quantity divalidasi sebagai bilangan bulat positif.
- Tidak ada baris item duplikat untuk kombinasi cart dan book jika kebijakan memilih agregasi kuantitas.
- Foreign key dan index sesuai.
- Database constraints melindungi konsistensi.
- Perubahan cart tidak memodifikasi Book.

## Penting: kuantitas e-book

UC-10 memang mengizinkan perubahan kuantitas.

Namun marketplace menjual lisensi buku digital, sehingga perlu diperiksa apakah pembelian beberapa lisensi buku yang sama diperbolehkan.

Jangan diam-diam mengubah ketentuan menjadi maksimal satu item per judul.

Sebaliknya, jangan mengasumsikan kuantitas lebih dari satu otomatis berarti beberapa hak akses untuk satu pengguna.

Periksa keputusan bisnis terbaru.

Implementasikan kontrak kuantitas secara konsisten dengan UC-10 dan sistem order. Jika arti multiple licenses belum disepakati, catat blocker aturan lisensi sebelum memungkinkan transaksi yang tidak jelas.

# 5. ADD TO CART — BACKEND BEHAVIOR

Alur:

```
Book Detail — Vayola
         |
         v
Tambah ke Keranjang
         |
         v
Authenticated Buyer?
         |
      +-- No --> Login
      |
      +-- Yes
             |
             v
       Validate Book
             |
             v
       Purchasable?
             |
             v
       Update Cart
             |
             v
       Return Cart State
             |
             v
       Update Cart Count
```

## Required checks

- Pembeli terautentikasi.
- Account status mengizinkan pembelian.
- Book tersedia.
- Book memiliki status yang boleh dibeli.
- Harga berasal dari database.
- Buku tidak milik penerbit yang sedang diblokir bila aturan publikasi mengharuskannya.
- Quantity memenuhi aturan.
- Request tidak dapat menambah item ke cart pengguna lain.

## Already-owned books

Periksa kontrak entitlement.

Jika pengguna sudah memiliki buku, jangan otomatis menjual buku tersebut lagi tanpa aturan bisnis yang jelas.

Tentukan behavior sesuai kebijakan:

- Menolak pembelian duplikat, atau
- Mendukung pembelian lisensi tambahan jika memang diperbolehkan.

Jangan menciptakan aturan bisnis tersebut secara sepihak.

Jangan membuat entitlement saat Add to Cart.

# 7. PRICING &amp; SUBTOTAL

Gunakan kontrak harga dari Dimas.

Contoh:

```
Buku A    1 × Rp 45.000 = Rp 45.000
Buku B    2 × Rp 30.000 = Rp 60.000

Subtotal                 Rp 105.000
```

Angka hanya ilustrasi.

Backend menghitung subtotal menggunakan nilai yang valid.

Gunakan integer Rupiah atau exact numeric arithmetic yang telah disepakati.

Jangan menggunakan floating-point untuk operasi uang.

## Cart price vs order snapshot

Harga keranjang dapat berubah sebelum checkout sesuai kebijakan harga produk.

Order yang dibuat Ghazy harus mempunyai snapshot harga final yang disahkan backend.

Jangan mengubah cart item menjadi order item secara diam-diam.

Jangan membuat record payment saat pengguna membuka keranjang.
