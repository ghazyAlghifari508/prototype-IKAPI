# 5. ORIGINAL PDF MUST REMAIN PRIVATE

Ini aturan keamanan wajib dari arsitektur IKAPI.

**Jangan mengirim original PDF ke browser pembeli.**

Dilarang:

- Public `/storage/books/original.pdf`.
- PDF asli lewat iframe.
- PDF.js yang mengunduh original PDF penuh lalu menyembunyikan tombol download.
- Signed URL yang memberikan akses ke original PDF penuh.
- Static bundle yang menyertakan PDF asli.
- Menaruh PDF source di folder public.
- Mempercayai frontend untuk membatasi halaman yang boleh diakses.

Buku disajikan melalui turunan halaman yang diproses backend.

## Security clarification

Pengiriman halaman hasil render mengurangi paparan PDF asli, tetapi bukan DRM sempurna.

Jangan mengklaim fitur dapat mencegah screenshot, screen recording, atau penyalinan konten secara mutlak.

Jangan menambahkan copy "100% anti-download" atau "DRM mutlak".

# 6. PAGE PROCESSING &amp; STORAGE

Audit implementasi upload PDF Dimas.

Periksa apakah:

- Original PDF sudah tersimpan privat.
- PDF sudah tervalidasi.
- Page count tersedia.
- Ada proses page rendering.
- Sudah ada derived page assets.
- File version/revision dapat diketahui.

Jika pipeline belum tersedia, implementasikan bagian reader yang diperlukan sesuai arsitektur.

## Processing approach

Gunakan server-side page rendering.

Sumber:

- Original PDF dari private storage.
- Backend memproses halaman.
- Derived page representation disimpan secara aman atau dihasilkan sesuai strategi yang dipilih.
- Browser menerima hanya halaman yang diotorisasi.

Evaluasi tooling PDF yang kompatibel dengan target Linux dan PHP/Laravel saat ini.

Jangan mengarang API library.

Gunakan dokumentasi resmi sebelum memilih dependency.

Jangan memasang beberapa PDF renderer sekaligus.

## Resource safety

PDF merupakan file tidak tepercaya sebelum tervalidasi.

Pertimbangkan:

- Batas ukuran.
- Batas jumlah halaman yang dapat diproses.
- Memory/CPU limits.
- Processing timeout.
- Failed conversion.
- Queue retries.
- Idempotent jobs.
- Cleanup.
- File replacement.
- Concurrency.
- Derived asset invalidation.

Untuk berkas besar, gunakan Laravel Queue jika diperlukan.

Jangan menjalankan proses konversi berat untuk setiap render React.

## Derived pages

Pastikan:

- Metadata page count valid.
- Page number tidak melewati batas.
- Derived pages terkait dengan versi PDF yang tepat.
- Mengganti PDF tidak mencampur halaman lama dan baru.
- Buku unpublished/taken down mengikuti access policy.
- File original tidak menjadi public resource.

Jangan membangun distributed processing system yang tidak dibutuhkan.

# 8. READING PROGRESS — PART OF UC-18

Ini **bukan** fitur bookmark.

Progress merupakan posisi baca terakhir.

Contoh:

```
Buku A
Total halaman: 180

Pengguna terakhir membaca halaman 42.

Saat membuka lagi:
Reader langsung menuju halaman 42.
```

Simpan progress berdasarkan:

- Authenticated User ID.
- Book ID.
- Page number.
- Updated timestamp.

Gunakan satu sumber data yang konsisten dengan Library Devina.

## Auto-save

Ketika halaman berubah:

- Reader memperbarui current page.
- Penyimpanan dilakukan ke backend.
- Jangan mengirim request berlebihan setiap re-render.
- Gunakan strategi debounce/throttle yang sesuai bila diperlukan.
- Tangani rapid navigation.
- Tangani response out of order.
- Hindari progress mundur akibat request lama yang selesai belakangan.
- Pastikan progress valid sebelum disimpan.

Jangan menganggap browser `beforeunload` sebagai satu-satunya mekanisme save.

## Resume

Pada pembukaan berikutnya:

- Ambil progress dari database.
- Validasi page masih ada.
- Gunakan page pertama bila belum ada progress.
- Jika page count berubah akibat revisi PDF, clamp/reconcile posisi dengan aturan yang aman.
- Jangan membuat reader gagal total karena progress di luar rentang.

## Separation from Bookmark

Progress hanya satu posisi terakhir yang relevan per buku/user.

Bookmark dapat terdiri dari beberapa halaman dan baru diimplementasikan pada Prompt 03.

Jangan menggunakan satu field bookmark sebagai pengganti progress.
