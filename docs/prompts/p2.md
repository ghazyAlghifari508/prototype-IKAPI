## 1. VERIFIED ORIGINAL PROBLEMS

In the original `komunitas_literasi_desktop(5).html`:

### Problem A — Profile Discussion Preview

Function:

`renderProfilePreview()`

Current pattern:

- Creates a button for the topic title.
- Clicking the title invokes `openTopic([topic.id](http://topic.id))`.
- Displays the author, reply count, and date as plain text metadata.

Example:

```
Rekomendasi buku pengantar filologi...
Nadia, 0 balasan, 2 hari lalu
```

Problem:

The text "0 balasan" looks like discussion information but has no dedicated interaction.

### Problem B — Discussion Room List

Function:

`buildTopicRow()`

Current pattern:

- Topic title is clickable.
- Reply-count control is also clickable.
- Reply-count control uses a chat icon.
- Clicking that control calls:

`openTopic([topic.id](http://topic.id), true)`

### Problem C — Unwanted Auto-Focus

In `openTopic(topicId, focusReply)`:

The `focusReply` argument can trigger:

- Scroll to `#reply-input`.
- Focus the composer instead of showing the top of the discussion.

This conflates two user intentions:

**Read Discussion** versus **Write Reply**.

### Problem D — Inconsistent Behavior

Profile and Discussion Room use different interaction patterns despite presenting the same kind of topic.

Fix these inconsistencies across all active pages.

## 2. FINAL UX DECISION

Use one explicit navigation action:

**[chat icon] [N balasan]**

The entire icon + text is one clickable target.

### Behavior

- `0 balasan`: clickable.
- `1 balasan`: clickable.
- `2 balasan`: clickable.
- `N balasan`: clickable.

When clicked:

**Navigate to Detail Topik and display the discussion from the top.**

Do not:

- Open the topic composer.
- Open Balas Komentar.
- Scroll to reply textarea.
- Automatically focus an input.
- Trigger login.
- Trigger community join.
- Trigger a modal.

### Important

User only wants to view the discussion when clicking the reply count.

Writing a reply remains a separate deliberate action within Detail Topik.

1. Topic title.

- Reply count must reflect actual stored visible replies.

### Click target

Do not make only the tiny icon clickable.

The icon and text must share one adequately sized interactive area.

Provide hover and focus states without turning it into a large purchase-style button.

## 5. SEMANTIC NAVIGATION

After Prompt 1, Detail Topik is a dedicated page or native route.

Use a **semantic link** for navigation, not a button that simulates navigation unnecessarily.

Concept:

```
<a href="detail_topik_komunitas_desktop.html?topik=...">
  <span aria-hidden="true">[chat icon]</span>
  <span>3 balasan</span>
</a>
```

The snippet is conceptual. Build the real URL from a validated topic ID using the project's shared navigation utility.

### Accessibility

- Preserve keyboard navigation.
- Focus indicator must be visible.
- Accessible name should identify the target.

Example accessible name:

"Lihat 3 balasan pada topik Rekomendasi Buku Pengantar Filologi"

For `0 balasan`:

"Lihat diskusi Rekomendasi Buku Pengantar Filologi, belum ada balasan"

Do not rely on the icon alone.

### Avoid nested interactive elements

Do not place a link inside another clickable card/button.

One navigation target is sufficient.

## 7. REPLY COUNT SOURCE

Use one shared count function.

Count:

- Visible root replies.
- Visible child replies.
- Visible deeper descendants.

Do not count:

- Removed replies.
- Replies belonging to another topic.
- Duplicate records.

If deleted parents remain as placeholders for their descendants, count only visible active contributions according to existing moderation policy.

### Example

```
Topic A
│
├── Reply Nadia
│   └── Reply Raka
│
└── Reply Dina

Visible reply count = 3
```

The same count must appear in:

- Community Profile preview.
- Discussion Room.
- Detail Topik heading.

Do not create three inconsistent counting implementations.

## 8. DETAIL TOPIK HEADER

## 9. MEMBERSHIP AND COMPOSER REGRESSION

Preserve the permission behavior fixed previously.

### Guest

- Can view public discussions.
- Cannot create a topic.
- Cannot write replies.

### Buyer, not joined

- Can view.
- Buat Topik remains disabled.
- No redirect from disabled button.

### Joined Buyer

- Can create topics.
- Can write replies.

### Important

The new reply-count link must work regardless of posting permission when the topic is public.

Clicking it must never initiate a login or membership change.

### No composer auto-focus

This applies to the topic title/reply-count navigation.

Do not remove the intended focus behavior when a user explicitly opens a writing interface.
