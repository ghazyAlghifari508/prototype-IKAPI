### Asset selection rules

Before placing an asset, determine:

- What the image actually depicts.
- Whether it fits the specific section's purpose.
- Whether its visual style matches other chosen assets.
- Whether it works at the intended size.
- Whether it has sufficient quality and resolution.
- Whether its colors harmonize with the design system.
- Whether the image adds value instead of just decoration.

Use the provided assets when appropriate.

Do NOT force all assets into the design.

Do NOT replace meaningful illustrations with generic gradients or abstract shapes merely because they are easier to create.

If an existing asset is unsuitable, explain why and choose the least disruptive alternative.

## 3. Establish the Correct Visual Direction

Design direction:

**Modern Editorial Bookstore, with contemporary e-commerce usability and IKAPI brand credibility.**

Required qualities:

- Welcoming.
- Visually distinctive.
- Book-focused.
- Modern and approachable.
- Appealing to younger digital shoppers without forced slang.
- Professional enough for the IKAPI ecosystem.
- Rich in relevant imagery.
- Easy to understand and navigate.

Do not interpret "Gen Z" as a request for neon gradients, oversized emoji, flashy colors, glassmorphism, or exaggerated animations.

The reference should guide the relationship between imagery, content, and layout.

### Color system

The previous prototype alternated between generic blue and green treatments.

Avoid switching the entire UI to another arbitrary color scheme.

Establish a small set of roles:

- Primary brand color.
- Secondary/supporting color.
- Background surface.
- Text color.
- Muted text.
- Border or divider.
- Action and interaction states.
- Rare semantic statuses when necessary.

The existing teal, dark green, and navy directions can be evaluated against the supplied references and actual visual assets.

Choose intentionally, not randomly.

Color variety should primarily come from the book artwork and selected editorial imagery.

### Typography

Use typography appropriate for a digital bookstore.

Assess the fonts in existing references and the current prototype.

Create a consistent scale for:

- Hero headline.
- Section heading.
- Product title.
- Author and publisher.
- Price.
- Body description.
- Navigation.
- Functional button labels.

Avoid:

- Unnecessarily tiny body text.
- Excessively bold text everywhere.
- Random uppercase micro-labels.
- Decorative typographic labels above every heading.
- Unnatural line breaks caused by arbitrary width constraints.

### Spacing and surfaces

Build a coherent layout grid.

Use consistent horizontal content alignment across sections.

Ensure appropriate desktop max-width and responsive margins.

Use open compositions where possible.

Do not surround every element with an identical card.

Avoid excessive white space that makes the screen feel unfinished.

Do not compress the layout so tightly that it becomes difficult to browse.

## 4. Remove Decorative AI-Slop Patterns

These are forbidden unless they communicate a real functional state:

- Decorative badges.
- Promotional emoji.
- Tiny colorful pills over every section.
- Floating dots.
- Glowing indicators.
- Random gradient panels.
- Glassmorphism labels.
- Arbitrary geometric ornaments.
- Decorative sparkles.
- Excessive corner rounding.
- Repeated SaaS feature cards.
- Repeated `eyebrow label → heading → paragraph → button` compositions.

Do not substitute one form of decoration for another.

Example:

BAD:

`[✨ PLATFORM RESMI]`

BAD REPLACEMENT:

`PLATFORM RESMI` as unnecessary uppercase microcopy.

CORRECT:

Remove the redundant label.

Preserve genuine functional controls such as dropdowns, selection indicators, cart counts, and status messages.

## 5. Redesign the Desktop Header

The current header is cleaner than the original, but it remains somewhat generic.

Improve:

- IKAPI Store branding.
- Search field prominence.
- Navigation spacing.
- Visual consistency.
- Cart action.
- Account actions.
- Category navigation.
- Publisher entry point, if supported.

Suggested structure:

```
┌───────────────────────────────────────────────────────────┐
│ IKAPI Store       [ Cari judul, penulis, atau penerbit ]   │
│                                             Masuk  Keranjang│
├───────────────────────────────────────────────────────────┤
│ Katalog   Kategori ▾   Agenda   Komunitas   Untuk Penerbit│
```

This is structural guidance, not a requirement to copy exact pixel positions.

If "Daftar" must remain visible according to the auth flow, retain it with appropriate hierarchy.

Do not remove necessary registration features purely for visual simplicity.

The category dropdown must use a real icon and clear behavior.

Never display a literal V character as an improvised chevron.

If the menu opens, design its open/closed states correctly.

If it is a normal link, avoid a misleading dropdown icon.

- The design still feels like a generic landing page.

## 7. Redesign Category Navigation

The existing category section is just a row of names separated by vertical lines.

It is functional in concept but visually underdeveloped and not comparable to the richer references.

Improve category discovery without turning it into another generic dashboard card grid.

Evaluate:

- Typographic category navigation.
- Carefully selected category imagery.
- Meaningful bookshelf illustration.
- Compact editorial categories.
- Responsive category browsing.

Suggested structure:

```
Telusuri Kategori

Sastra        Pendidikan       Budaya
Bisnis        Anak & Remaja

[ Lihat Semua Kategori ]
```

Visual grouping and layout should be refined.

Do not require these exact columns or arrangement.

Do not invent category inventory counts.

Avoid decorative emoji and excessive colorful icons.

Use category imagery only when genuinely useful.

Do not make each category a large identical rounded card by default.

## 8. Preserve Visual Consistency Across Sections

The header, hero, and category treatment must establish a visual system that can be reused by later tasks.

Define or refine:

- Text styles.
- Button variants.
- Layout spacing.
- Container widths.
- Background roles.
- Product media rules.
- Icon rules.
- Divider behavior.
- Navigation states.

Prefer updating existing reusable components/styles instead of duplicating nearly identical structures.

If FigCraft supports component properties, styles, or variables for the relevant elements, use them where appropriate.

Do not introduce unnecessary abstractions just to create a design system.
