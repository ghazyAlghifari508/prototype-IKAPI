## 1. Setup pengamatan yang valid

- Verifikasi branch dan source final; jangan mengganti HTML original.
- Jalankan HTML melalui HTTP server pada origin lokal yang stabil, bukan mengandalkan perilaku `file://` ketika localStorage dipakai antarhalaman.
- Gunakan browser engine, deviceScaleFactor, zoom, timezone, locale, font loading, animasi, viewport, dan data state **yang dikontrol dan didokumentasikan**. Jangan membandingkan screenshot dari dua browser berbeda.
- Catat ketergantungan CDN/fonts/image eksternal dan kegagalan network. Pastikan screenshot diambil setelah font, gambar, dan konten selesai dimuat; hindari loading placeholder sebagai baseline kecuali sedang menguji loading state.

## 2. Coverage minimum

Untuk setiap halaman kanonis dari P01:

1. Screenshot full-page + viewport screenshot untuk desktop `1440×900`, `1366×768`, tablet `768×1024`, mobile `390×844` dan narrow `320×700` jika desain memungkinkan. Adaptasikan ke referensi mobile aktual; catat fallback.
2. Capturing first fold, section penting, footer, responsive menu/scroll region, overflow.
3. Semua interaction states yang memang ada: default, hover/focus, active tab, empty/filtered/no-results, open modal/drawer, validation error, success, disabled, dropdown, loading, preview, public/member/role demo. Tidak perlu menangkap seluruh permutasi yang identik; pilih matriks per komponent/state agar coverage lengkap namun efisien.
4. Per halaman catat topologi screenshot dan data fixture yang diperlukan untuk mereproduksi state; jangan ubah sample data persisten user hanya untuk screenshot.
5. Verifikasi aset gambar, font, SVG, crop/object-fit dan transform. Simpan referensi URL/path asli dan checksum/hash file yang penting.

## 3. Metrik dan defect baseline

- Rekam computed style untuk elemen representatif: body font, heading, container width, section padding, grid gaps, card radius, text colors, line-height, border, nav height, avatar/image sizes, z-index.
- Identifikasi baseline defects **yang sudah ada di HTML** (misalnya broken image, layout overflow, misleading click, JS error). Jangan memperbaikinya diam-diam; catat path, viewport, state dan bukti. Ini membedakan bug lama dari regresi migrasi.
- Sediakan visual diff methodology: lokasi golden PNG, perbandingan viewport yang sama, diff/overlay dan toleransi hanya untuk font anti-aliasing atau animasi yang nondeterministik, bukan toleransi terhadap spacing/font/crop yang berubah.

## 4. Deliverables

Simpan `docs/migration/[p2-visual-baseline.md](http://p2-visual-baseline.md)` dengan manifest screenshot (source HTML → route/viewport/state), environment, baseline defects, visual tokens, ringkasan interaksi, serta cara mereproduksi. Simpan screenshot baseline pada direktori baru di luar original HTML mis. `docs/migration/baselines/` atau lokasi artifact terpisah bila repo menghindari binary besar; dokumentasikan lokasi dan stabilkan naming.

**Gate:** tak boleh lanjut P03 jika halaman prioritas (homepage, catalog, detail buku, keranjang, community, login, publisher dashboard, admin dashboard) belum punya baseline yang dapat dipakai untuk compare. Untuk halaman lain, harus ada rencana capture lengkap sebelum konversinya dimulai. Tidak mengubah application code.
