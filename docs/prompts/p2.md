### Prototype Directory & Route Naming Convention

To prevent filename collisions with the starter kit's built-in pages (such as `pages/settings/` or `pages/auth/`) and to keep development-only code isolated:

1. **Root page folder:** All interactive prototype views MUST be placed under `resources/js/pages/prototype/`.
2. **Flexible hierarchy:** Pages do not need to be flat; organize them hierarchically according to feature complexity:

   - Multi-page or modular features: `resources/js/pages/prototype/<feature-name>/<sub-page>.tsx` (e.g., `prototype/katalog/index.tsx`, `prototype/pembayaran/status.tsx`, `prototype/settings/account.tsx`).
3. **Route prefix:** Expose prototype pages in `routes/web.php` strictly using the `/prototype/...` URL prefix (e.g., `Route::inertia('/prototype/<feature>', 'prototype/<feature>/...');`).
