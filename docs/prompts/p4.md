# TASK: Redesign Preview Buku IKAPI Store — Clean Reading Experience, Functional Pagination &amp; Scroll

## 1. Konteks dan Tujuan

Perbaiki halaman preview buku pada:

`preview_buku_desktop.html`

Baca dan pahami seluruh HTML, styling, JavaScript, dan interaksinya sebelum melakukan perubahan.

**Jangan sekadar mengganti warna. Benahi struktur pengalaman membaca secara menyeluruh.**

# 6. Typography dan Reading Comfort

Ini merupakan prioritas penting.

## Masalah

Konten menggunakan Plus Jakarta Sans dengan paragraf justified dan heading sangat tebal.

Plus Jakarta Sans cocok untuk UI, tetapi belum tentu ideal untuk bacaan panjang pada ukuran yang digunakan sekarang.

Selain itu, `text-justify` dapat menghasilkan jarak antarkata yang tidak konsisten.

## Rekomendasi

Pisahkan tipografi antarmuka dan tipografi bacaan.

### UI

Pertahankan Plus Jakarta Sans untuk:

- Header.
- Navigasi.
- Tombol.
- Indikator halaman.
- Kontrol pembelian.

### Isi buku

Gunakan font bacaan yang nyaman, misalnya:

- Literata.
- Georgia.
- Atau font bacaan lain yang memang cocok dengan bentuk teks.

Pilih satu yang konsisten, bukan mengganti font pada setiap section.

### Ukuran dan keterbacaan

- Ukuran teks desktop sekitar 17–18px.
- Ukuran teks mobile sekitar 16–17px.
- Line-height sekitar 1.65–1.8.
- Lebar paragraf sekitar 60–75 karakter pada desktop.
- Gunakan alignment kiri secara default jika justify menyebabkan spasi tidak merata.
- Jarak antarparagraf harus cukup.
- Judul bab menonjol tanpa menjadi sangat besar.
- Hindari font weight terlalu tebal pada teks panjang.

Jangan menggunakan dua atau tiga jenis font dekoratif sekaligus.

### Aksesibilitas

- Teks harus bisa dipilih dengan mouse atau keyboard.
- Hapus `select-none` pada area bacaan.
- Hormati text scaling dan zoom browser.
- Pastikan paragraf tidak terpotong saat browser zoom 200%.
- Jangan mengunci tinggi teks.
- Hindari warna teks terlalu terang pada latar krem.

# 8. Perbaikan Pagination dan Progress

## Masalah yang ditemukan

Pada HTML sekarang:

- `currentPageIndex = 2`
- `totalPages = 12`
- `samplePages` hanya berisi empat objek halaman.

Tampilan dimulai dari:

**Sampel 3 / 12**

Tetapi jumlah halaman yang memiliki konten tidak sesuai dengan total yang ditampilkan.

Navigasi Berikutnya dibatasi berdasarkan panjang `samplePages`, sementara indikator progress menggunakan `totalPages = 12`.

Ini menyebabkan progress tidak akurat.

## Perbaikan wajib

Gunakan jumlah halaman yang benar-benar tersedia.

Jika terdapat empat halaman cuplikan yang valid, tampilkan:

**1 / 4**

Pada saat membuka reader untuk pertama kali, mulai dari halaman pertama.

Jangan mulai dari halaman ketiga tanpa alasan.

### Wireframe navigasi

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  [ ← Sebelumnya ]        Halaman 1 dari 4   [ Berikutnya → ]│
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### Perilaku

- Halaman pertama: Sebelumnya disabled.
- Halaman tengah: kedua tombol aktif.
- Halaman terakhir: Berikutnya disabled.
- Progress mengikuti halaman yang benar.
- Perpindahan halaman memperbarui konten dan angka halaman secara bersamaan.
- Jangan membiarkan progress menunjukkan halaman yang tidak tersedia.
- Jangan membuat fallback halaman kosong untuk memenuhi angka total palsu.
- Jangan menampilkan placeholder "Bagian sampel lanjutan..." sebagai halaman buku.

### State management

Gunakan satu sumber data untuk:

- Jumlah halaman.
- Konten halaman.
- Current page.
- Progress.

Jangan menduplikasi konstanta jumlah halaman yang dapat saling bertentangan.

### Pemeriksaan JavaScript

Periksa referensi elemen DOM seperti:

- `header-page-indicator`
- `page-counter-badge`
- `page-progress-bar`
- `page-footer-note`
- `btn-prev`
- `btn-next`

Pastikan semua elemen yang diperbarui benar-benar tersedia setelah redesign.

Jangan mempertahankan referensi DOM lama yang sudah dihapus.

Jika indikator tertentu tidak lagi dibutuhkan, bersihkan JavaScript terkait.

# 9. Perilaku Perpindahan Halaman

Ketika pengguna menekan Berikutnya:

1. Konten halaman berubah.
2. Indikator halaman diperbarui.
3. Progress diperbarui.
4. Reader kembali ke awal halaman baru agar pengguna tidak mulai membaca dari bagian tengah atau bawah.

Ketika menekan Sebelumnya, berlaku perilaku yang sama.

### Hal yang harus dicegah

- Konten berubah tetapi posisi scroll masih berada di bawah.
- Progress tidak berubah.
- Tombol tetap aktif saat halaman terakhir.
- Navigasi menyebabkan halaman bergeser secara horizontal.
- Scroll langsung melompat ke navbar yang tidak relevan.
- Heading halaman baru tertutup sticky header.

Gunakan scroll positioning yang sesuai dengan container membaca.

Jangan menambahkan animasi page-flip 3D yang berat.

Transisi sederhana diperbolehkan, tetapi tidak wajib.

Jika memakai animasi, hormati `prefers-reduced-motion`.

# 11. Perbaikan Scrolling

**WAJIB: halaman reader dapat di-scroll dengan normal.**

Ini termasuk salah satu acceptance criteria utama.

## Masalah yang perlu diperiksa

HTML saat ini memiliki:

`::-webkit-scrollbar { display: none; }`

dan wrapper reader menggunakan:

`select-none`

Selain itu terdapat pengaturan tinggi container yang perlu diperiksa agar tidak menyebabkan konten terpotong pada viewport tertentu.

Jangan langsung menganggap salah satu CSS tersebut sebagai penyebab pasti scroll gagal. Periksa perilaku aktual.

## Persyaratan scrolling

### Desktop

- Mouse wheel berfungsi.
- Touchpad berfungsi.
- PageDown dan PageUp berfungsi.
- Konten panjang bisa dibaca sampai akhir.
- Scrollbar tidak disembunyikan secara global.
- Tidak ada scroll lock.
- Header tidak menutupi konten.
- Navigasi halaman tetap bisa dicapai.

### Mobile

- Swipe vertikal berfungsi.
- Paragraf tidak terpotong.
- Tidak ada horizontal overflow.
- Halaman dapat dibaca sampai akhir.
- Tombol kembali bisa dijangkau.
- Pagination tidak keluar viewport secara horizontal.
- Tidak ada container fixed-height yang menjebak scrolling.

### Perbaikan CSS

- Hindari `overflow: hidden` pada root halaman.
- Jangan menyembunyikan scrollbar global.
- Gunakan `min-height` daripada fixed height jika konten perlu bertambah.
- Jangan membuat wrapper membaca terkunci pada satu ukuran viewport.
- Jangan menambahkan nested scrolling tanpa kebutuhan.
- Hapus `select-none` pada konten bacaan.
- Periksa perilaku sticky header apabila digunakan.

### Perilaku saat berpindah halaman

Pastikan posisi scroll kembali ke awal konten halaman baru.

Jangan membuat scrolling global melompat secara tidak terduga.
